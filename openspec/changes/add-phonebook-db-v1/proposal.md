# Proposal: add-phonebook-db-v1 — BUDB v1

## Why

Нужна база данных имён и телефонов, которая быстро отвечает на два вопроса: «кто звонит с этого номера» (CUJ-01) и «какой телефон у этого человека» (CUJ-02). Подтверждённая запись не должна теряться при сбое (CUJ-03, CUJ-07), а 10^8 контактов должны помещаться на одном узле (D-024). Существующие СУБД и движки брать нельзя: базу нужно написать с нуля. Репозиторий пуст (`openspec/specs/` не содержит спецификаций), поэтому это первый change: в нём задаётся весь продукт v1.

## What Changes

- Новая система BUDB: один бинарник `budb` с подкомандами `serve` и `admin` (D-032, BLD-10, CLI-01).
- Собственный движок хранения: один файл, страницы 4 KiB с CRC32C, две мета-страницы, COW B+tree, MVCC, group commit, fail-stop (STO-01…STO-24).
- Модель данных и правила нормализации имён и телефонов (CON, NAM, PHN), поиск точный и по префиксу (SRCH).
- HTTP API `/api/v1` с OpenAPI 3.1, RFC 9457, ETag/If-Match, `Idempotency-Key`, асинхронным импортом и экспортом (API, IMP).
- Веб-UI с WCAG 2.2 AA и ru/en (UI); Admin CLI для онлайн- и офлайн-операций (CLI).
- Безопасность: локальные учётные записи reader/writer/admin, bearer-токены, cookie-сессии, TLS, CSP (ACL).
- ПДн: корзина 1…29 дней, purge с физическим затиранием, журнал purge, аудит без ПДн (PRV).
- Онлайн-бэкап, restore, verify, офлайн-компактизация (BKP); метрики, логи, `/livez`, `/readyz` (OBS).
- SLO, бенчмарк и условие выпуска (PERF); ограничения сборки и обязательные тесты надёжности (BLD).
- Итог: 15 capability, 270 требований, 487 сценариев (`docs/traceability.md`). Breaking changes нет: это первый выпуск.
- Решения D-034…D-060 приняты после написания спецификаций и в части требований ещё не отражены. Расхождения перечислены в `design.md` (раздел «Решения, ещё не отражённые в спецификациях»); их исправит редактор после ревью. До исправления действует решение.

## Capabilities

### New Capabilities

Ровно список D-029.

- `contacts`: агрегат Contact, лимиты полей, создание, чтение, изменение с проверкой версии, корзина, подсказка о дубликатах (CON-01…CON-19).
- `phone-normalization`: разбор ввода в E.164 с добавочным номером, регион, проверка «возможного» номера, версия правил (PHN-01…PHN-16).
- `name-normalization`: хранение имени в NFC, очистка, поисковый ключ, версия правил и переиндексация (NAM-01…NAM-12).
- `search`: точный и префиксный поиск по телефону и имени, порядок, пагинация, видимость записей (SRCH-01…SRCH-15).
- `import-export`: CSV (RFC 4180) и NDJSON, задания импорта с пробным прогоном, потоковый экспорт снимка, защита от CSV-инъекции (IMP-01…IMP-16).
- `storage-engine`: формат файла, COW B+tree, мета-страницы, MVCC, протокол коммита, восстановление, fail-stop (STO-01…STO-24).
- `backup-restore`: онлайн-бэкап из снимка, restore с атомарной подменой, verify, компактизация, ротация (BKP-01…BKP-12).
- `performance-capacity`: масштаб, SLO, пропускная способность, память, диск, метод измерения, backpressure (PERF-01…PERF-16).
- `build-constraints`: NFR-SCRATCH, политика зависимостей, toolchain, платформы, единый бинарник, обязательные тесты надёжности (BLD-01…BLD-19).
- `observability`: живость, готовность, метрики Prometheus, структурированные логи без ПДн (OBS-01…OBS-15).
- `http-api`: ресурсы `/api/v1`, ошибки, условные и идемпотентные запросы, лимиты, фоновые задачи, совместимость (API-01…API-28).
- `web-ui`: поиск при вводе, карточка, форма, конфликты, корзина, импорт, экспорт, состояние, доступность, локализация (UI-01…UI-23).
- `admin-cli`: подкоманды `serve` и `admin`, онлайн- и офлайн-режим, коды выхода, машиночитаемый вывод (CLI-01…CLI-16).
- `access-control`: учётные записи и роли, пароли, токены, сессии, CSRF, TLS, CSP и заголовки (ACL-01…ACL-22).
- `data-privacy`: ПДн по 152-ФЗ и GDPR: минимизация, сроки хранения, purge, журнал purge, аудит, маскирование, выгрузка субъекта (PRV-01…PRV-17).

### Modified Capabilities

Нет: в `openspec/specs/` пока нет ни одной спецификации.

## Impact

- **Код:** новый Rust-workspace (stable, edition 2024, MSRV ≥ 1.89, `#![forbid(unsafe_code)]`, D-020) и UI на TypeScript, собираемый закреплённым `tsc` (D-060). Кода пока нет.
- **Публичные контракты v1:** HTTP API `/api/v1` и документ OpenAPI (API-02, API-03); команды и коды выхода `budb` (CLI-13); формат файла БД и бэкапа версии 1 (STO-01, BKP-02); форматы CSV и NDJSON (IMP).
- **Зависимости:** только allowlist (D-021, D-033, D-038, D-060); denylist проверяется по всему транзитивному графу (BLD-04).
- **Файлы на диске:** файл БД; журнал аудита и журнал purge — отдельные файлы только на добавление (D-055, D-036); бэкапы с ротацией 30…180 дней (D-037).
- **Эксплуатация:** нужен супервизор, который перезапускает процесс после fail-stop (D-034); полные гарантии — только на Linux tier 1 и на накопителях, честно исполняющих сброс кэша (D-019, D-023); мониторинг метрик и алертов (OBS, D-035).
- **Право:** имена и телефоны — ПДн; сроки корзины и бэкапов, purge и аудит рассчитаны на 152-ФЗ (D-012, D-045, D-049). Это требования учебного проекта, а не юридическая консультация.
- **Процесс:** ID требований стабильны (D-040); трассировка CUJ → требования перегенерируется командой `node scripts/traceability.mjs`.
