# Proposal: add-phonebook-db-v1 — BUDB v1

## Why

Нужна база данных имён и телефонов, которая быстро отвечает на два вопроса: «кто звонит с этого номера» (CUJ-01) и «какой телефон у этого человека» (CUJ-02). Подтверждённая запись не должна теряться при сбое (CUJ-03, CUJ-07), а 10^8 контактов должны помещаться на одном узле (D-024). Существующие СУБД и движки брать нельзя: базу нужно написать с нуля. Репозиторий пуст (`openspec/specs/` не содержит спецификаций), поэтому это первый change: в нём задаётся весь продукт v1.

### Что значит «хорошая база данных»

Вводная 1 оценочная, поэтому по D-084 она раскрыта в проверяемые критерии. Каждый критерий проверяется требованиями и тестами из указанных capability; невыполнение любого из них — отказ в выпуске (PERF-16, BLD-05).

| Критерий | Что измеряется или проверяется | Где задано |
|---|---|---|
| ACID в пределах транзакции | Атомарность изменения всех деревьев одной транзакцией; изоляция снимков MVCC (читатель видит одно подтверждённое состояние); проверка версии при изменении (412); один писатель | `storage-engine` (STO-06…STO-09, STO-11, STO-12), `contacts` (CON-13), `http-api` (API-08) |
| Гарантии долговечности | Подтверждение только после сброса страниц и мета-страницы; нет режима без долговечности; порча — явная ошибка, а не тихий откат; обнаружение потерянных и промахнувшихся записей; переписывание мета-страницы при открытии; честная оговорка о накопителе | `storage-engine` (STO-11…STO-21, STO-23, STO-25, STO-26, STO-34), `backup-restore` (BKP-01…BKP-17); ADR 0005 |
| SLO | Точный поиск p99 ≤ 2 мс (тёплый кэш), префиксный p99 ≤ 50 мс, запись p50 ≤ 15 мс и p99 ≤ 60 мс, открытие ≤ 1 с, API p99 ≤ 100 мс, ≥ 5 000 поисков/с и ≥ 500 записей/с, файл ≤ 4 ГБ на 10^7, RTO ≤ 10 мин; SLO CUJ — 28 дней, 99,9 % | `performance-capacity` (PERF-04…PERF-08, PERF-11, PERF-12, PERF-16, PERF-18), `docs/cuj.md`; D-024, D-060, D-066, D-094 |
| Безопасность | Роли и матрица прав, хэши паролей и токенов, cookie и CSRF, TLS, CSP, область токена `metrics`, квота выдачи, защита от подбора без DoS, ПДн не в URL, аудит каждого действия с ПДн, затирание при purge | `access-control` (ACL-01…ACL-26), `data-privacy` (PRV-01…PRV-20), `http-api` (API-10, API-13, API-19); таблица OWASP API Top 10 в `access-control` |
| Наблюдаемость | `/livez`, `/readyz` с режимами отказа, метрики Prometheus (задержки, долговечность, откат мета-страницы, удержание и затирание страниц, свободное место на ФС), структурированные логи без ПДн | `observability` (OBS-01…OBS-21) |
| Стратегия тестирования | Модельные property-тесты, детерминированная симуляция с моделью сбоев (в том числе потерянные и промахнувшиеся записи), сбой на каждом системном вызове, перебор состояний в стиле ALICE, kill -9 и LazyFS, ошибки сброса на реальном ядре (dm-error, dm-flakey), тесты конкурентности (loom), фаззинг, verify после каждого теста, бюджеты на PR и ночью, предрелизный длительный прогон | `build-constraints` (BLD-12…BLD-27); ADR 0015; D-026, D-097 |

## What Changes

- Новая система BUDB: один бинарник `budb` с подкомандами `serve` и `admin` (D-032, BLD-10, CLI-01).
- Собственный движок хранения: один файл, страницы 4 KiB с заголовком (`page_no`, `write_txid`, CRC32C), две мета-страницы с `page_count`, COW B+tree, freelist как дерево `free_db`, MVCC с кооперативным отзывом снимков, group commit, fail-stop и degraded-read-only (STO).
- Модель данных и правила нормализации имён и телефонов (CON, NAM, PHN), поиск точный и по префиксу (SRCH).
- HTTP API `/api/v1` с OpenAPI 3.1, RFC 9457 (резолвимый `type` и поле `code`), ETag/If-Match, `Idempotency-Key`, API сессий, асинхронным импортом и экспортом (API, IMP).
- Веб-UI с WCAG 2.2 AA и ru/en (UI); Admin CLI для онлайн- и офлайн-операций, включая повторную нормализацию телефонов и схему конфигурации (CLI).
- Безопасность: локальные учётные записи reader/writer/admin, bearer-токены с областью `metrics`, cookie-сессии, `public_origin` и доверенные прокси, TLS, CSP, квота выдачи (ACL).
- ПДн: корзина 1…29 дней, purge с состояниями `pending`/`done` и затиранием всех освобождённых страниц, журнал purge, аудит по каждому событию без ПДн, `subjects:erase` (PRV).
- Онлайн-бэкап (в том числе периодический), restore с защитой от разрыва журнала purge и новой линией БД, verify со сверкой бэкапа и снимка, офлайн-компактизация (BKP); метрики, логи, `/livez`, `/readyz` (OBS).
- SLO, бенчмарк и условие выпуска (PERF); ограничения сборки, изоляция `unsafe` и обязательные тесты надёжности (BLD).
- Итог: 15 capability; число требований и сценариев после правок раунда 1 пересчитывает `node scripts/traceability.mjs` (`docs/traceability.md`). Breaking changes нет: это первый выпуск.
- Решения D-034…D-106 приняты после написания спецификаций; редакторы вносят их по таблице «Решения после ревью раунда 1» в `design.md` (журналы правок — `docs/reviews/round1-fixlog-*.md`). До внесения действует решение.

## Capabilities

### New Capabilities

Ровно список D-029. Диапазоны ID — на 2026-10-24, по ходу правок раунда 1; ID не перенумеровываются (D-040).

- `contacts`: агрегат Contact, лимиты полей, создание, чтение, изменение с проверкой версии, корзина, подсказка о дубликатах (CON-01…CON-19).
- `phone-normalization`: разбор ввода в E.164 с добавочным номером, регион, проверка «возможного» номера, версия правил (PHN-01…PHN-17).
- `name-normalization`: хранение имени в NFC, очистка, поисковый ключ, версия правил и переиндексация (NAM-01…NAM-13).
- `search`: точный и префиксный поиск по телефону и имени, порядок, пагинация, видимость записей (SRCH-01…SRCH-17).
- `import-export`: CSV (RFC 4180) и NDJSON, задания импорта с пробным прогоном, потоковый экспорт снимка, защита от CSV-инъекции (IMP-01…IMP-17).
- `storage-engine`: формат файла и страниц, COW B+tree, мета-страницы, `free_db`, MVCC, протокол коммита, восстановление, fail-stop и degraded-read-only, затирание освобождённых страниц (STO-01…STO-39).
- `backup-restore`: онлайн- и периодический бэкап из снимка, restore с атомарной подменой, verify, компактизация, ротация (BKP-01…BKP-17).
- `performance-capacity`: масштаб, SLO, пропускная способность, память, диск, метод измерения, backpressure, RTO (PERF-01…PERF-18).
- `build-constraints`: NFR-SCRATCH, политика зависимостей, toolchain, `budb-sys`, платформы, единый бинарник, обязательные тесты надёжности (BLD-01…BLD-27).
- `observability`: живость, готовность, метрики Prometheus, структурированные логи без ПДн (OBS-01…OBS-21).
- `http-api`: ресурсы `/api/v1`, ошибки, условные и идемпотентные запросы, сессии, лимиты, фоновые задачи, совместимость (API-01…API-35).
- `web-ui`: поиск при вводе, карточка, форма, конфликты, корзина, импорт, экспорт, состояние, доступность, локализация (UI-01…UI-26).
- `admin-cli`: подкоманды `serve` и `admin`, онлайн- и офлайн-режим, коды выхода, машиночитаемый вывод, схема конфигурации (CLI-01…CLI-19).
- `access-control`: учётные записи и роли, пароли, токены и области, сессии, CSRF, TLS, CSP и заголовки, квоты (ACL-01…ACL-26).
- `data-privacy`: ПДн по 152-ФЗ и GDPR: минимизация, сроки хранения, purge, журнал purge, аудит, маскирование, выгрузка и стирание данных субъекта, ограничения (PRV-01…PRV-20).

### Modified Capabilities

Нет: в `openspec/specs/` пока нет ни одной спецификации.

## Impact

- **Код:** новый Rust-workspace (stable, edition 2024, MSRV ≥ 1.89; `#![forbid(unsafe_code)]` во всех крейтах, кроме изолированного `budb-sys`, D-020, D-090) и UI на TypeScript, собираемый закреплённым `tsc` (D-060). Кода пока нет.
- **Публичные контракты v1:** HTTP API `/api/v1` и документ OpenAPI (API-02, API-03), включая `type` и `code` ошибок (D-099); команды, ключи конфигурации и коды выхода `budb` (CLI-13, CLI-18); формат файла БД и бэкапа версии 1 с заголовком страницы, `page_count`, `db_lineage_id` и `free_db` (STO-01…STO-04, STO-25…STO-27, BKP-02); форматы CSV и NDJSON (IMP).
- **Зависимости:** только allowlist (D-021, D-033, D-038, D-060, D-066, D-082, D-097); denylist проверяется по всему транзитивному графу (BLD-04).
- **Файлы на диске:** файл БД; журнал аудита и журнал `purge.journal` — отдельные файлы только на добавление (D-055, D-036, D-084); бэкапы — пара `<ts>.budb` и `<ts>.purge` с ротацией 30…180 дней (D-037).
- **Эксплуатация:** нужен супервизор, который перезапускает процесс после fail-stop с нарастающей задержкой (D-034, D-072); при порче или нехватке места узел остаётся в режиме degraded-read-only и продолжает чтения (D-078, D-089); в конфигурации задаются `public_origin` и `trusted_proxies` (D-101); Prometheus получает токен с областью `metrics` (D-103); полные гарантии — только на Linux tier 1 и на накопителях, честно исполняющих сброс кэша (D-019, D-023); мониторинг метрик и алертов (OBS, D-035).
- **Право:** имена и телефоны — ПДн; сроки корзины и бэкапов, purge и аудит по каждому событию рассчитаны на 152-ФЗ (D-012, D-049, D-100); purge не заменяет сертифицированное СЗИ (D-105). Это требования учебного проекта, а не юридическая консультация.
- **Процесс:** ID требований стабильны (D-040); трассировка CUJ → требования перегенерируется командой `node scripts/traceability.mjs`.
