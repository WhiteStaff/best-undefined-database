# Tasks

Чек-лист реализации BUDB v1 по фазам. Как строить, описано в `design.md`; что строить — в спецификациях (ID требований). Формат задачи: что сделать — **Требования:** ID — **Готово:** критерий проверки. Решения D-034…D-106 важнее текста спецификаций, если он им противоречит (`design.md`, раздел «Решения после ревью раунда 1»). Задачи, добавленные после ревью раунда 1, ссылаются на решения D-NNN; там, где ID нового требования ещё не закреплён редактором, указана capability. Каждая фаза приносит свои тесты и документацию; последняя фаза — только интеграционные crash-тесты.

## 1. Каркас и CI с политикой зависимостей

- [ ] 1.1 Создать Cargo-workspace: крейты движка, домена, сервера и бинарника `budb`; stable, edition 2024, `rust-version` ≥ 1.89, `#![forbid(unsafe_code)]` в каждом крейте, кроме `budb-sys` (D-090) — **Требования:** BLD-06, BLD-07, BLD-10 — **Готово:** CI собирает и тестирует на stable и на MSRV; проверка в CI находит `forbid(unsafe_code)` в каждом `lib.rs`/`main.rs`, кроме `budb-sys`.
- [ ] 1.2 Настроить `deny.toml`: allowlist прямых зависимостей (D-021, D-033, D-038, D-060), test-only крейты, denylist по всему транзитивному графу — **Требования:** BLD-01, BLD-02, BLD-03, BLD-04 — **Готово:** `cargo deny check bans` зелёный; контрольные ветки с `sled` в транзитивных зависимостях, с `serde` в крейте движка и с `proptest` в релизном графе падают.
- [ ] 1.3 Добавить в CI проверки на каждое изменение: `cargo deny check bans`, `cargo build --locked`, `openspec validate --all --strict`, `node scripts/traceability.mjs --check`; любое нарушение блокирует слияние — **Требования:** BLD-05 — **Готово:** защищённая ветка не принимает PR с нарушением любой из проверок.
- [ ] 1.4 Матрица CI: Linux x86_64 и aarch64 (tier 1), Windows x86_64 и macOS aarch64 (tier 2); оговорки tier 2 в документации — **Требования:** BLD-09 — **Готово:** все четыре цели зелёные; в руководстве оператора есть раздел про rename и каталог на Windows.
- [ ] 1.5 Воспроизводимая сборка: `Cargo.lock` в репозитории, релиз только с `--locked` — **Требования:** BLD-11 — **Готово:** две сборки одного коммита на одной платформе дают одинаковый SHA-256 бинарника.
- [ ] 1.6 Ввести трейты `Storage`, `Clock`, `Rng`; движок не вызывает `std::fs`, системное время и ГПСЧ напрямую — **Требования:** BLD-12 — **Готово:** проверка в CI не находит прямых вызовов в крейте движка; есть реализации `OsDisk` и заглушка `SimDisk`.
- [ ] 1.7 Крейт `budb-sys` (D-090, ADR 0018): единственное место с `unsafe` — FFI (`MoveFileExW` с `MOVEFILE_WRITE_THROUGH`, вызовы `libc`) и intrinsics CRC32C с определением возможностей во время выполнения; наружу — только безопасный API — **Требования:** BLD-07, BLD-20, STO-15 — **Готово:** CI находит `unsafe` только в `budb-sys`; перед каждым `unsafe`-блоком есть `// SAFETY:` (`clippy::undocumented_unsafe_blocks`); тесты `budb-sys` проходят под Miri там, где он применим; изменения крейта требуют ревью двух рецензентов (CODEOWNERS).
- [ ] 1.8 Allowlist после ревью: `chacha20poly1305` (D-082), dev-зависимости `tempfile`, `criterion` (D-066), test-only `loom` (D-097) — **Требования:** BLD-02, BLD-03 — **Готово:** `cargo deny check bans` зелёный; `loom` и `criterion` отсутствуют в релизном графе.

## 2. CRC32C и формат страниц

- [ ] 2.1 Реализовать CRC32C (Castagnoli) табличным способом; аппаратный путь — только через `budb-sys` с определением возможностей во время выполнения и с совпадающим результатом (D-090) — **Требования:** BLD-08, BLD-20 — **Готово:** тест-векторы RFC 3720 прил. B.4 проходят (подтверждены EX1 F1, F2); property-тест «аппаратный = табличный» на случайных буферах.
- [ ] 2.2 Кодирование страницы: заголовок {magic и тип, `page_no`, `write_txid`, CRC32C по всей странице} (D-085), ручное кодирование чисел без serde — **Требования:** STO-03 — **Готово:** юнит-тесты round-trip; страница с изменённым битом и страница с чужим `page_no` отвергаются.
- [ ] 2.3 Заголовок файла (страница 0) и проверки при открытии — **Требования:** STO-01, STO-02 — **Готово:** сценарии STO-01 и STO-02 проходят; хеш файла до и после отказа совпадает.
- [ ] 2.4 Мета-страница: txid, `page_count` (D-086), `db_lineage_id` (D-095), корни (`page_no`, `write_txid`) трёх деревьев, каталога и `free_db` (D-091), `next_contact_id`, версии правил, счётчики (`design.md`, раздел 2) — **Требования:** STO-04, STO-26, STO-38, STO-39 — **Готово:** round-trip; сценарий «Чередование слотов» проходит на SimDisk.
- [ ] 2.5 Фаззинг разбора страницы, мета-страницы и заголовка — **Требования:** BLD-16 — **Готово:** цели cargo-fuzz работают ≥ 1 ч за ночь без паники и зависаний; найденные входы лежат в регрессионном корпусе.
- [ ] 2.6 Указатели (`page_no`, ожидаемый `write_txid`) в ветвях и в мета-странице и проверка при каждом чтении с диска (D-085) — **Требования:** STO-25, STO-03 — **Готово:** подмена страницы валидной страницей с другим номером (misdirected write) и старой версией той же страницы (lost write) обнаруживается как повреждение в юнит-тестах.

## 3. B+tree в памяти и модельные тесты

- [ ] 3.1 B+tree поверх абстракции страниц в памяти: вставка, удаление, точный и диапазонный поиск, префиксный скан; кодирование ключей `id`, `kind‖key‖0x00‖id`, `digits‖0x00‖id` (`design.md`, раздел 2) — **Требования:** STO-06, SRCH-08 — **Готово:** сценарии порядка SRCH-08 проходят на уровне дерева.
- [ ] 3.2 Страницы переполнения для записей и ключей больше 1 КиБ, укороченные разделители в ветвях — **Требования:** CON-01, CON-03 — **Готово:** контакт максимального размера по D-022 сохраняется и читается; верификатор структуры дерева зелёный.
- [ ] 3.3 Модельные property-тесты (proptest-state-machine) против модели в памяти: создание, изменение, удаление, точный и префиксный поиск по имени и телефону — **Требования:** BLD-15 — **Готово:** ≥ 10 000 последовательностей за прогон CI; внедрённая ошибка сжимается до минимального контрпримера.

## 4. COW и коммит

- [ ] 4.1 Кэш страниц с ограниченным размером (по умолчанию 512 МиБ), проверка CRC32C при каждой загрузке, без mmap — **Требования:** STO-22, PERF-09 — **Готово:** сценарии STO-22 проходят; в `/proc/<pid>/maps` нет файла БД; кэш меньше минимума отклоняется при запуске.
- [ ] 4.2 COW-транзакция, аллокатор и COW-дерево `free_db(freeing_txid → [page_no])` по образцу FREE_DBI LMDB, собственные страницы `free_db` учитываются в том же коммите (D-091); правило переиспользования T+2 (`design.md`, раздел 3.1) — **Требования:** STO-05, STO-10, STO-27 — **Готово:** сценарии STO-05, STO-10, STO-27 проходят; тест «откат по D-035 после переиспользования» не находит подменённых страниц; инвариант «каждая страница < `page_count` ровно в одном множестве» проверяется после каждой транзакции модельного теста.
- [ ] 4.3 Реестр снимков, MVCC-читатели, лимит 30 с для интерактивных снимков и тайм-аут запроса 2 с (D-078), кооперативный отзыв по флагу при каждой загрузке страницы (D-092), отзыв самого старого снимка при удержании > 25 % файла (D-093), длинные снимки — до T_purge − 1 ч (D-076) — **Требования:** STO-09, STO-24, STO-31, STO-32 — **Готово:** сценарии проходят; читатель не блокирует писателя в тесте с удержанием снимка 10 с; страницы отозванного снимка не переиспользуются до снятия регистрации.
- [ ] 4.4 Протокол коммита (1)…(4), чередование слотов, платформенные примитивы сброса (rename на Windows через `budb-sys`, D-090), fsync каталога; сброс намерений аудита параллельно со сбросом данных — два последовательных сброса на коммит (D-094) — **Требования:** STO-11, STO-12, STO-14, STO-15 — **Готово:** трасса системных вызовов на Linux и macOS совпадает с `design.md`, раздел 3; сценарии STO-11, STO-12, STO-14, STO-15 проходят на SimDisk.
- [ ] 4.5 Поток-писатель, ограниченная очередь, group commit с точками отката — **Требования:** STO-08, STO-13, PERF-14 — **Готово:** сценарии STO-08 и STO-13 проходят (50 запросов — ровно два сброса); переполнение очереди даёт отказ без побочных эффектов.
- [ ] 4.6 Эксклюзивная блокировка файла — **Требования:** STO-20 — **Готово:** вторая копия процесса завершается ошибкой, файл не меняется; после kill -9 блокировка берётся снова.
- [ ] 4.7 Атомарность транзакции над всеми деревьями; конфигурация с отключённым сбросом отвергается — **Требования:** STO-07, STO-21 — **Готово:** сценарии STO-07 и STO-21 проходят.
- [ ] 4.8 Атомарное создание файла БД и рост файла предвыделением: запись нулей и сброс региона до использования; ENOSPC при расширении или проверке места — 507 и degraded-read-only, а не fail-stop (D-072) — **Требования:** STO-33, STO-36, STO-35 — **Готово:** kill -9 посреди создания не оставляет файла с итоговым именем; тест SimDisk с ENOSPC до шага (3): запись получает 507, чтения продолжаются, fail-stop не наступает.
- [ ] 4.9 Обнуление освобождённых страниц: каждая освобождённая страница затирается нулями со сбросом, как только это разрешает правило 3.1, не больше K за коммит, не позднее T_purge (D-102); служебные коммиты по таймеру, пока есть страницы для затирания (D-070) — **Требования:** STO-28, STO-29 — **Готово:** после PUT контакта и истечения T_purge в симулированном времени побайтовый поиск старого значения в файле ничего не находит; на простаивающей системе затирание завершается без пользовательских записей.

## 5. Восстановление и fault injection

- [ ] 5.1 Открытие и восстановление по `design.md`, раздел 4.1: выбор мета-страницы по D-063, обрезка до `page_count` (D-086), переписывание выбранной мета-страницы со сбросом до готовности (D-088), правило T+2 для отложенных страниц после перезапуска (D-087) — **Требования:** STO-17, STO-18, STO-26, STO-34 — **Готово:** сценарии проходят; при откате растёт `budb_meta_fallback_total`, в логе txid валидного слота; ошибка переписывания мета-страницы — отказ в открытии.
- [ ] 5.2 Fail-stop по D-034 только при ошибках записи и сброса файла БД и журнала аудита (D-065, D-078): отказ текущим записям, «исход неизвестен» на шаге (4), 503 ≤ 5 с, выход с отдельным кодом — **Требования:** STO-16 — **Готово:** тест SimDisk с EIO на fsync: fsync не повторяется, чтения не обслуживаются, процесс выходит ≤ 5 с с ожидаемым кодом, после перезапуска состояние берётся с диска.
- [ ] 5.3 Полная модель сбоев SimDisk: потеря несброшенного, порванные записи по 512 Б, EIO, битовые ошибки, потерянные (lost) и промахнувшиеся (misdirected) записи, порча подтверждённых страниц и мета-страниц (D-097); прогон по seed — **Требования:** BLD-12, BLD-25 — **Готово:** ≥ 1 000 seed на PR и ≥ 100 000 за ночь (бюджеты PR и ночи, D-084); любое падение воспроизводится по seed; внедрённые lost и misdirected writes обнаруживаются проверкой D-085.
- [ ] 5.4 Ошибка на каждом i-м системном вызове коммита и открытия — **Требования:** BLD-13 — **Готово:** для каждого i: подтверждения нет, движок в fail-stop, после перезапуска состояние до или после транзакции и проходит verify.
- [ ] 5.5 Перебор состояний после сбоя в стиле ALICE по трассе коммита — **Требования:** BLD-14 — **Готово:** во всех сгенерированных состояниях видна последняя подтверждённая транзакция или более поздняя целиком.
- [ ] 5.6 Офлайн-верификатор (ядро BKP-08) и его запуск после каждого сценария надёжности — **Требования:** BLD-19 — **Готово:** внедрённая утечка страницы проваливает сборку.
- [ ] 5.7 Время открытия после сбоя — **Требования:** PERF-07 — **Готово:** p99 ≤ 1 с на 10^7 контактов после kill -9 на эталонном стенде.
- [ ] 5.8 Раздел руководства оператора о гарантиях долговечности — **Требования:** STO-23 — **Готово:** в нём есть оговорка о честном сбросе накопителя и ссылка на FAST 2013.
- [ ] 5.9 Режим degraded-read-only (D-078, D-089): порча страницы во время работы даёт 500 этому запросу, записи — 503, чтения обслуживаются, `/readyz` = 200 со статусом `degraded-read-only`; режим снимает только admin после verify или restore — **Требования:** STO-19, STO-35, OBS-02, API-31 — **Готово:** тест SimDisk с испорченным листом: процесс не завершается, цикла рестартов нет, поиск по другим ключам работает, метрика и алерт выставлены.
- [ ] 5.10 Тесты конкурентности кэша страниц, реестра снимков и пула читателей на `loom` (только для тестов, D-097) — **Требования:** BLD-21 — **Готово:** модели loom для захвата и отзыва снимка и вытеснения страницы проходят; внедрённая гонка (освобождение снимка до снятия регистрации) находится.
- [ ] 5.11 Ошибки сброса на реальном ядре Linux через dm-error и dm-flakey в CI (D-097) — **Требования:** BLD-22 — **Готово:** при EIO на fsync движок не повторяет сброс, уходит в fail-stop, после перезапуска с шагом 5.1 (D-088) подтверждённые данные на месте, неподтверждённые отсутствуют.
- [ ] 5.12 Порванный хвост журналов аудита и purge (STO-37) — **Требования:** STO-37 — **Готово:** порванная последняя запись отбрасывается и файл обрезается; неверная CRC32C в середине — явная ошибка открытия.

## 9. Безопасность

- [ ] 9.1 Учётные записи, роли, матрица прав (с D-041), проверка на каждом запросе, 401 и 403 — **Требования:** ACL-01, ACL-02, ACL-03, ACL-04, API-21 — **Готово:** табличный тест «роль × эндпоинт» совпадает с матрицей; новый эндпоинт без правила закрыт.
- [ ] 9.2 Пароли: argon2, политика длины, NFC — **Требования:** ACL-05, ACL-06 — **Готово:** сценарии проходят; пароль не встречается в файле БД, логах и аудите.
- [ ] 9.3 Токены: формат, SHA-256 секрета, сравнение за постоянное время, срок, отзыв — **Требования:** ACL-07, ACL-08, ACL-09, ACL-10 — **Готово:** сценарии проходят; отзыв действует со следующего запроса.
- [ ] 9.4 Сессии в памяти, cookie по D-043 и D-101 (атрибуты по схеме `public_origin`), тайм-ауты 30 мин бездействия и 8 ч абсолютный (D-066), выход — **Требования:** ACL-11, ACL-12, ACL-13 — **Готово:** сценарии проходят; e2e-тест cookie на `http://127.0.0.1` во всех поддерживаемых браузерах.
- [ ] 9.5 CSRF и `Sec-Fetch-Site` — **Требования:** ACL-14 — **Готово:** межсайтовый запрос и запрос без токена получают 403 `csrf-failed`.
- [ ] 9.6 Защита от подбора без жёсткой блокировки: прогрессивная задержка по (логин, IP), лимит по IP, алерт администратору (D-104); единый ответ при неудаче — **Требования:** ACL-15, ACL-16 — **Готово:** атакующий с одного IP не блокирует вход того же логина с другого IP; сценарии проходят; время ответа для трёх случаев неотличимо в статистическом тесте.
- [ ] 9.7 TLS на rustls: минимум 1.2 по умолчанию, 1.3 предпочтителен (D-066); адрес прослушивания по умолчанию — **Требования:** ACL-17, ACL-18 — **Готово:** рукопожатие TLS 1.1 отклоняется; внешний адрес без сертификата не запускается.
- [ ] 9.8 CSP и заголовки безопасности — **Требования:** ACL-19, ACL-20 — **Готово:** каждый ответ содержит заголовки из ACL-19 и ACL-20; внедрённый inline-скрипт не исполняется.
- [ ] 9.9 Нет учётных записей по умолчанию, первичная инициализация администратора — **Требования:** ACL-21 — **Готово:** на новой базе любой вход отклоняется до `bootstrap`.
- [ ] 9.10 Нет исходящих запросов по данным пользователя — **Требования:** ACL-22 — **Готово:** интеграционный тест в сети без выхода наружу проходит весь импорт; кода загрузки по URL нет.
- [ ] 9.11 `public_origin` и `trusted_proxies` (D-101): проверки `Origin` и `Sec-Fetch-*` против `public_origin`, IP клиента из `X-Forwarded-For` только от доверенных прокси; CORS выключен — **Требования:** ACL-23, ACL-26, ACL-14, OBS-19 — **Готово:** за TLS-терминирующим прокси cookie получает `Secure` и `__Host-`; `X-Forwarded-For` от недоверенного адреса игнорируется.
- [ ] 9.12 Область токена `metrics` (только `GET /metrics`, D-103) и квота выданных контактов на токен (reader — 10 000 в час по умолчанию) с алертом на перебор (D-083) — **Требования:** ACL-24, ACL-25, OBS-03, API-19 — **Готово:** токен `metrics` получает 403 на всё, кроме `/metrics`; превышение квоты — 429 и событие аудита; бенчмарк использует токен без лимита (D-073).

## 10. Корзина, purge и аудит

- [ ] 10.1 Срок корзины 1…29 дней (по умолчанию 7), автоочистка ≤ 24 ч после срока (D-049) — **Требования:** PRV-03, PRV-04 — **Готово:** сценарии в редакции 0.1 проходят; срок 30 и больше не даёт запуститься.
- [ ] 10.2 Purge по `design.md`, раздел 5: запись `pending` до транзакции N, перезапись страниц с производными формами, включая разделители (D-077), служебный коммит N+1, отзыв снимков до T_purge − 1 ч (D-076), затирание, запись `done`, квитанция; удаление результатов экспорта и `idempotency_keys` (D-065, D-084) — **Требования:** PRV-01, PRV-05, PRV-06, PRV-07, PRV-08, STO-30, API-24 — **Готово:** после статуса `erased` побайтовый поиск по каталогу данных не находит ни одной производной формы (`display_name` NFC, ключ NFKC_Casefold, ключи слов, цифры `e164`, `raw_input`); долгий экспорт закрыт, его файл удалён; бэкап перезапускается.
- [ ] 10.3 Журнал `purge.journal` без хэшей с копией в каталоге бэкапов (D-036, D-042, D-084); запись = `purge_id`, `contact_id`, `created_at` контакта, время, исполнитель, состояние `pending`/`done` (D-075, D-076); повтор `pending` при запуске — **Требования:** PRV-09 — **Готово:** запись не содержит ПДн и хэшей; kill -9 до N, между N и N+1 и до затирания: после перезапуска purge доводится до `done`, квитанция не врёт.
- [ ] 10.4 Журнал аудита по D-100: по одному событию с `contact_id` для чтения по `id`, результатов точного поиска, экспорта, `subjects:search`, всех изменений, входа и админ-операций; агрегаты на пользователя за минуту — только для префиксных поисков typeahead; ошибка записи аудита — fail-stop (D-065); ротация; чтение только admin — **Требования:** PRV-12, PRV-13 — **Готово:** чтение контакта по `id` даёт событие с этим `id`; сценарии проходят; журнал не содержит ПДн; writer получает 403 на `GET /api/v1/admin/audit`.
- [ ] 10.5 Маскирование ПДн в логах сервера и CLI — **Требования:** PRV-14 — **Готово:** лог ошибки валидации содержит `+7**********` и не содержит цифр номера.
- [ ] 10.6 Выгрузка данных субъекта: активные контакты по индексам, корзина — перебором `trash_idx` — **Требования:** PRV-15 — **Готово:** сценарии проходят; выгрузка записана в аудит.
- [ ] 10.7 Минимизация данных и документация о локализации — **Требования:** PRV-02, PRV-17 — **Готово:** поле `note` даёт 422; в руководстве по развёртыванию есть раздел о размещении базы и бэкапов в РФ.
- [ ] 10.8 Линия аудита (lineage): намерения с txid, `boot_id` и `db_lineage_id` до коммита; компенсирующие записи `rolled_back` только для намерений упавшего запуска в той же линии с txid больше восстановленного (D-080, D-095) — **Требования:** PRV-12, STO-38, OBS-08 — **Готово:** kill -9 после записи намерения и до мета-страницы даёт `rolled_back`; после restore на старый бэкап подтверждённые события прежней линии не помечаются как откаченные.
- [ ] 10.9 Скачок часов: при расхождении настенных и монотонных часов больше 1 ч автоочистка корзины и ротация бэкапов приостанавливаются до подтверждения admin, алерт (D-081) — **Требования:** PRV-04, BKP-12 — **Готово:** тест с `Clock`, прыгающим на +10 лет, не очищает корзину и не удаляет бэкапы.
- [ ] 10.10 Документация ограничений: purge — техническая мера, не сертифицированное СЗИ (152-ФЗ ст. 19 ч. 2 п. 3.1), копии в FTL SSD и снимках томов не стираются (D-105) — **Требования:** PRV-19, STO-23 — **Готово:** раздел есть в руководстве оператора и в описании capability `data-privacy`.
