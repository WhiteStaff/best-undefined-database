# import-export

## Purpose

Определяет массовый импорт и экспорт контактов BUDB в CSV (RFC 4180) и NDJSON: асинхронные задания импорта с пробным прогоном и построчным отчётом, применение пакетами, политику дубликатов `on_conflict`, потоковый экспорт согласованного снимка, обратимость экспорта, удаление результатов экспорта при purge и защиту от CSV-инъекции. Права на импорт и экспорт задаёт access-control.

## ADDED Requirements

### Requirement: IMP-01 Форматы и кодировка
Импорт и экспорт SHALL поддерживать ровно два формата: CSV по RFC 4180 и NDJSON, оба только в UTF-8. Запрос другого формата MUST отклоняться до создания задания. Метка порядка байтов UTF-8 в начале файла импорта SHALL пропускаться [ПРЕДЛОЖЕНИЕ АГЕНТА]; экспорт CSV разделяет записи CRLF, NDJSON — LF.
Трассировка: CUJ-06; ADR-0010; D-016
Источник: docs/research/03 §4.8

#### Scenario: Неподдерживаемый формат
- **WHEN** writer запускает импорт файла в формате vCard
- **THEN** запуск отклоняется ошибкой «формат не поддерживается», задание не создаётся

#### Scenario: CSV с BOM
- **WHEN** импортируется CSV-файл, начинающийся с байтов `EF BB BF`
- **THEN** первая колонка заголовка распознаётся как `display_name`, а не как `﻿display_name`

### Requirement: IMP-02 Колонки CSV
Первая строка CSV SHALL быть заголовком из колонок `display_name`, `given_name`, `family_name`, `middle_name`, `phone_N`, `phone_N_label` (N = 1…10) и служебных `id`, `version`, `created`, `updated`, которые импорт игнорирует (CON-19) [ПРЕДЛОЖЕНИЕ АГЕНТА]. `display_name` обязательна; неизвестная или повторная колонка MUST отклонять весь импорт до применения записей.
Трассировка: CUJ-06; ADR-0007; D-009, D-016, D-022, D-071

#### Scenario: Колонка заметки
- **WHEN** заголовок CSV содержит колонку `note`
- **THEN** задание завершается со `status` = `failed` с ошибкой заголовка, ни одна запись не применена

#### Scenario: Минимальный заголовок
- **WHEN** заголовок CSV содержит только `display_name,phone_1`
- **THEN** заголовок принимается

#### Scenario: Служебные колонки игнорируются
- **WHEN** импортируется CSV с колонками `id,version,display_name` и строкой `5,3,Анна`
- **THEN** создаётся контакт «Анна» с новым `id` и `version` = 1, строка не считается ошибочной

### Requirement: IMP-03 Телефоны в файлах
Телефон SHALL передаваться в файле одной строкой: при импорте исходная строка из файла нормализуется по phone-normalization и сохраняется как `raw_input`, при экспорте выводится каноническая форма `e164` или `e164;ext=N`. Первый телефон записи CSV MUST считаться основным; экспорт SHALL выводить основной телефон первым [ПРЕДЛОЖЕНИЕ АГЕНТА].
Трассировка: CUJ-06; ADR-0008; D-009, D-010, D-054
Источник: docs/research/03 §1.2

#### Scenario: Импорт национального номера
- **WHEN** импортируется запись с `phone_1` = `8 912 345-67-89` при регионе RU
- **THEN** у контакта основной телефон `+79123456789` с `raw_input` = `8 912 345-67-89`

#### Scenario: Экспорт добавочного номера
- **WHEN** в NDJSON экспортируется контакт с `e164` = `+74951234567` и `extension` = `101`
- **THEN** в файле телефон записан как `+74951234567;ext=101`

### Requirement: IMP-04 Записи NDJSON
Строка NDJSON SHALL быть объектом с `display_name`, частями имени и `phones` из объектов `{raw_input, label, is_primary, region}` (CON-04). Экспорт MUST писать контакт такой же строкой с `raw_input` по IMP-03 и полями `id`, `version`, `created`, `updated`, которые импорт игнорирует (CON-19). Строка с неизвестным полем (например, заметкой) SHALL быть ошибочной.
Трассировка: CUJ-05, CUJ-06; ADR-0007, ADR-0010; D-016, D-054, D-071

#### Scenario: Корректная строка
- **WHEN** импортируется строка `{"display_name":"Анна","phones":[{"raw_input":"+79123456789","label":"mobile"}]}`
- **THEN** создаётся контакт «Анна» с мобильным телефоном `+79123456789`

#### Scenario: Строка из файла экспорта
- **WHEN** импортируется строка `{"id":"1050","version":3,"created":"2026-10-01T10:00:00.000Z","updated":"2026-10-02T10:00:00.000Z","display_name":"Анна","phones":[{"raw_input":"+79123456789","label":"mobile","is_primary":true}]}`
- **THEN** создаётся контакт «Анна» с новым `id`, `version` = 1 и основным мобильным `+79123456789`, строка не считается ошибочной

#### Scenario: Строка с заметкой
- **WHEN** импортируется строка с полем `"note"`
- **THEN** строка попадает в отчёт как ошибочная, остальные строки обрабатываются

### Requirement: IMP-05 Задание импорта
Запуск импорта SHALL создавать задание и возвращать его идентификатор до обработки записей; параметры — формат, пробный прогон, `on_conflict` (IMP-11), регион (PHN-08). Задание MUST следовать модели задач API-32 (`queued` → `running` → `succeeded` или `failed` с `reason`), переживать перезапуск и показывать счётчики обработанных, применённых, пропущенных и ошибочных записей.
Трассировка: CUJ-06; ADR-0010; D-016, D-032, D-064, D-084

#### Scenario: Асинхронный запуск
- **WHEN** writer запускает импорт файла из 100 000 записей
- **THEN** ответ с идентификатором задания в состоянии `queued` или `running` приходит до применения всех записей
- **AND** по идентификатору видны растущие счётчики

#### Scenario: Завершение с ошибочными строками
- **WHEN** импорт файла из 10 записей, одна из которых ошибочна, завершён
- **THEN** задание имеет `status` = `succeeded`, обработано 10, применено 9, ошибочных 1

### Requirement: IMP-06 Очередь заданий импорта
Одновременно SHALL выполняться не более одного задания импорта, а в очереди могут ждать не более 4 заданий [ПРЕДЛОЖЕНИЕ АГЕНТА]. Запуск сверх очереди MUST отклоняться ошибкой перегрузки (PERF-14) без создания задания.
Трассировка: CUJ-06, CUJ-08; ADR-0017; D-032

#### Scenario: Переполнение очереди
- **WHEN** одно задание выполняется, четыре ждут, и запускается шестое
- **THEN** запуск отклоняется ошибкой перегрузки, задание не создаётся

### Requirement: IMP-07 Пробный прогон
В режиме пробного прогона задание SHALL выполнять разбор, валидацию, нормализацию и проверку политики дубликатов всех записей и строить такой же отчёт, как обычный импорт, но MUST NOT изменять данные.
Трассировка: CUJ-06; ADR-0010; D-016
Источник: docs/research/03 §4.8

#### Scenario: Пробный прогон с ошибками
- **WHEN** пробный прогон выполняется для файла из 100 записей, 3 из которых содержат недопустимые телефоны
- **THEN** отчёт показывает 97 записей к применению и 3 ошибочные
- **AND** число контактов в базе не изменилось

### Requirement: IMP-08 Построчный отчёт
Отчёт задания SHALL перечислять каждую отклонённую запись с номером её первой строки в файле, указателем на поле и кодом ошибки (например, из PHN-14) и MUST NOT содержать значений полей [ПРЕДЛОЖЕНИЕ АГЕНТА]. В отчёт SHALL попадать первые 1000 ошибок [ПРЕДЛОЖЕНИЕ АГЕНТА] и общее их число.
Трассировка: CUJ-06, CUJ-09; ADR-0010; D-012, D-013

#### Scenario: Ошибка телефона в строке 5
- **WHEN** в строке 5 файла телефон `12`
- **THEN** отчёт содержит запись: строка 5, поле `phone_1`, код `phone.invalid_length`
- **AND** значение `12` в отчёте отсутствует

#### Scenario: Много ошибок
- **WHEN** в файле 5000 ошибочных записей
- **THEN** отчёт содержит 1000 записей об ошибках и общее число ошибок 5000

### Requirement: IMP-09 Применение пакетами
Корректные записи SHALL применяться в порядке файла пакетами по 1000 записей [ПРЕДЛОЖЕНИЕ АГЕНТА]; каждый пакет MUST фиксироваться атомарно и долговечно (storage-engine). Ошибочная запись пропускается и не отменяет пакет. Отчёт SHALL показывать номер последней строки последнего зафиксированного пакета.
Трассировка: CUJ-03, CUJ-06; ADR-0005; D-019, D-032

#### Scenario: Ход применения
- **WHEN** импорт 2500 корректных записей зафиксировал два пакета
- **THEN** в базе ровно 2000 новых контактов, и отчёт указывает последнюю строку второго пакета

### Requirement: IMP-10 Прерывание импорта
Если импорт прерван сбоем процесса или синтаксической ошибкой, после которой нельзя найти границы записей, задание SHALL перейти в `failed` с `reason` = `interrupted` или `syntax-error`. Зафиксированные пакеты MUST остаться применёнными, а записи незафиксированного — не применяться даже частично. Продолжения импорта в v1 нет: файл импортируется заново с `on_conflict` = `skip_exact`.
Трассировка: CUJ-06, CUJ-07; ADR-0005; D-019, D-053, D-084

#### Scenario: Сбой процесса
- **WHEN** процесс аварийно завершается во время третьего пакета и перезапускается
- **THEN** задание показывается со `status` = `failed` и `reason` = `interrupted`
- **AND** в базе ровно записи первых двух пакетов

#### Scenario: Незакрытая кавычка
- **WHEN** в CSV на строке 1501 открыта кавычка, не закрытая до конца файла
- **THEN** задание завершается со `status` = `failed`, `reason` = `syntax-error` и строкой 1501, первый пакет остаётся применённым

#### Scenario: Повторный запуск после сбоя
- **WHEN** после прерванного импорта с двумя зафиксированными пакетами тот же файл импортируется с `on_conflict` = `skip_exact`
- **THEN** записи первых двух пакетов учитываются как пропущенные, остальные создаются, дубликатов нет

### Requirement: IMP-11 Политика дубликатов
Параметр `on_conflict` SHALL принимать ровно `create_always` (по умолчанию: каждая корректная запись создаёт новый контакт) и `skip_exact`: запись пропускается, если активный контакт (в том числе созданный этим импортом) имеет тот же полный ключ имени и тот же набор пар (`e164`, `extension`). Другое значение MUST отклоняться до создания задания; `id` из файла игнорируется.
Трассировка: CUJ-06; ADR-0007; D-009, D-053, D-071

#### Scenario: create_always
- **WHEN** в базе есть «Анна» с `+79123456789`, и импортируется та же запись без указания политики
- **THEN** создаётся второй контакт «Анна»

#### Scenario: skip_exact
- **WHEN** тот же файл импортируется с `on_conflict` = `skip_exact`
- **THEN** запись учитывается как пропущенная, новый контакт не создаётся

#### Scenario: Неизвестная политика
- **WHEN** импорт запускается с `on_conflict` = `merge`
- **THEN** запуск отклоняется ошибкой валидации, задание не создаётся

### Requirement: IMP-12 Лимиты размера импорта
Файл импорта MUST быть не больше лимита загрузки (API-18, по умолчанию 1 ГиБ), а одна запись — не больше 64 КиБ [ПРЕДЛОЖЕНИЕ АГЕНТА]. Превышение размера файла SHALL отклонять импорт без создания задания; слишком длинная запись SHALL считаться ошибочной, а импорт — продолжаться.
Трассировка: CUJ-06, CUJ-08; ADR-0010; D-032
Источник: docs/research/03 §4.6, §6.1 (API4)

#### Scenario: Большой файл
- **WHEN** при лимите по умолчанию загружается файл размером 1,5 ГиБ
- **THEN** импорт отклоняется ошибкой превышения размера, задание не создаётся

#### Scenario: Длинная строка NDJSON
- **WHEN** строка 7 файла NDJSON имеет длину 70 КиБ
- **THEN** строка 7 попадает в отчёт как ошибочная, следующие строки обрабатываются

### Requirement: IMP-13 Экспорт согласованного снимка
Экспорт SHALL выдавать ровно активные контакты одного согласованного снимка, взятого в момент начала экспорта, упорядоченные по `id` [ПРЕДЛОЖЕНИЕ АГЕНТА]. Записи, подтверждённые после начала, и контакты в корзине MUST NOT попадать в экспорт; поведение при purge во время экспорта — по IMP-17.
Трассировка: CUJ-06, CUJ-07; ADR-0003; D-018, D-084
Источник: docs/research/03 §4.8

#### Scenario: Запись во время экспорта
- **WHEN** во время экспорта 1 000 000 контактов подтверждается создание нового контакта
- **THEN** файл содержит ровно 1 000 000 контактов без нового

#### Scenario: Корзина не экспортируется
- **WHEN** в базе 10 активных контактов и 2 в корзине
- **THEN** экспорт содержит 10 контактов

### Requirement: IMP-14 Потоковый экспорт
Экспорт SHALL формироваться потоком: записи MUST записываться в результат (файл задачи API-26 или вывод admin-cli) по мере чтения снимка, а память, занимаемая экспортом, MUST NOT расти с числом контактов. Пропускная способность — по performance-capacity (PERF).
Трассировка: CUJ-06, CUJ-08; ADR-0010; D-024

#### Scenario: Экспорт большой базы
- **WHEN** запускается экспорт базы из 10^7 контактов
- **THEN** первые записи появляются в результате до того, как прочитана вся база
- **AND** занимаемая экспортом память не зависит от числа контактов

### Requirement: IMP-15 Защита от CSV-инъекции
При экспорте в CSV ячейка, начинающаяся с `=`, `+`, `-`, `@`, `'`, Tab, CR, LF или полноширинных `＝`, `＋`, `－`, `＠`, SHALL получать префикс `'` и заключаться в двойные кавычки [ПРЕДЛОЖЕНИЕ АГЕНТА], в том числе в колонках телефонов. При импорте CSV ровно один ведущий `'` перед символом из этого набора SHALL удаляться. NDJSON MUST NOT экранироваться.
Трассировка: CUJ-06; ADR-0010; D-016, D-060, D-106
Источник: OWASP CSV Injection

#### Scenario: Формула в имени
- **WHEN** экспортируется контакт с `display_name` = `=HYPERLINK("x")`
- **THEN** значение ячейки в CSV равно `'=HYPERLINK("x")`, а ячейка заключена в двойные кавычки

#### Scenario: Полноширинный знак
- **WHEN** экспортируется контакт с `display_name` = `＝1+1`
- **THEN** значение ячейки в CSV равно `'＝1+1`

#### Scenario: Телефон в CSV
- **WHEN** экспортируется телефон `+79123456789`
- **THEN** значение ячейки CSV равно `'+79123456789`
- **AND** при импорте этого файла телефон читается как `+79123456789`

#### Scenario: Апостроф в начале имени
- **WHEN** экспортируется имя `'Bob`, а затем файл импортируется
- **THEN** в CSV записано `''Bob`, после импорта имя снова `'Bob`

### Requirement: IMP-16 Обратимость экспорта
Импорт файла экспорта (NDJSON или CSV) в пустую базу SHALL проходить без ошибочных строк и воспроизводить для каждого контакта `display_name`, части имени и телефоны (`e164`, `extension`, `label`, основной). `id`, `version`, `created`, `updated` MUST назначаться заново, а `raw_input` становится канонической формой из файла (IMP-03).
Трассировка: CUJ-06, CUJ-07; ADR-0007; D-016, D-054, D-071
Источник: docs/research/03 §7.4

#### Scenario: Круговой перенос NDJSON
- **WHEN** база экспортирована в NDJSON, и файл импортирован в пустую базу
- **THEN** задание импорта завершается со `status` = `succeeded` и 0 ошибочных строк
- **AND** мультимножества пар (имя и его части, телефоны) в обеих базах совпадают

#### Scenario: Круговой перенос CSV
- **WHEN** база с контактом `display_name` = `=SUM(1)` и телефоном `+79123456789` экспортирована в CSV, и файл импортирован в пустую базу
- **THEN** контакт воспроизводится с `display_name` = `=SUM(1)` и основным телефоном `+79123456789`, ошибочных строк нет

### Requirement: IMP-17 Экспорт и purge
Purge по запросу (`:purge`, `subjects:erase`) SHALL принудительно завершать выполняющиеся задания экспорта, начатые до него, со `status` = `failed` и `reason` = `contact-purged` без файла результата. Готовые файлы экспорта с этим контактом или номером MUST удаляться сразу при любом purge, в том числе автоочистке (PRV-16); запрос результата получает 410 (API-26). Автоочистка (PRV-04) MUST NOT прерывать выполняющиеся задания.
Трассировка: CUJ-06, CUJ-09; ADR-0012; D-065, D-084, D-119, D-121

#### Scenario: Экспорт выполняется во время purge
- **WHEN** admin выполняет purge контакта, пока идёт задание экспорта, начатое раньше
- **THEN** задание экспорта завершается со `status` = `failed` и `reason` = `contact-purged`, файла результата нет

#### Scenario: Автоочистка во время экспорта
- **WHEN** идёт задание экспорта, а автоочистка корзины очищает контакт с истёкшим сроком
- **THEN** задание экспорта не прерывается и завершается со `status` = `succeeded`, а контакта из корзины в файле нет (IMP-13)

#### Scenario: Готовый экспорт содержит контакт
- **WHEN** admin выполняет purge контакта, который есть в готовом файле экспорта
- **THEN** файл результата удалён, и запрос результата этой задачи получает 410

#### Scenario: Автоочистка и готовый экспорт
- **WHEN** срок корзины 1 сутки, экспорт с контактом завершился до его удаления, и автоочистка очищает контакт
- **THEN** файл результата удалён сразу, а запрос результата получает 410

#### Scenario: Готовый экспорт без контакта
- **WHEN** контакт создан после завершения экспорта и затем очищен
- **THEN** файл результата этого экспорта сохраняется

### Requirement: IMP-18 Хранение загруженного файла импорта
Загруженный файл импорта SHALL храниться во временном каталоге рядом с БД и удаляться по окончании задания, а при сбое — не позже чем через 24 ч. Purge по запросу MUST удалять все хранящиеся файлы загрузки и переводить активное задание импорта в `failed` с `reason` = `contact-purged`; автоочистка корзины (PRV-04) MUST NOT трогать импорт.
Трассировка: CUJ-06, CUJ-09; ADR-0010, ADR-0012; D-065, D-113, D-118, D-119

#### Scenario: Задание завершено
- **WHEN** задание импорта перешло в `succeeded` или `failed`
- **THEN** загруженный файл удалён из временного каталога

#### Scenario: Файл брошенного задания
- **WHEN** задание прервано, и прошло 24 ч
- **THEN** загруженный файл удалён

#### Scenario: Purge при хранящемся файле
- **WHEN** admin выполняет purge по запросу любого контакта, пока хранится файл загрузки импорта
- **THEN** файл удалён, а активное задание этого импорта имеет `status` = `failed` и `reason` = `contact-purged`

#### Scenario: Автоочистка при хранящемся файле
- **WHEN** автоочистка корзины очищает контакт, пока идёт импорт и хранится файл загрузки
- **THEN** файл не удалён, а задание импорта продолжается и не получает `contact-purged`
