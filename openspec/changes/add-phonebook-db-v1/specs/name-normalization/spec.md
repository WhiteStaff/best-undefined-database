# name-normalization

## Purpose

Определяет, как BUDB хранит имена контактов и строит из них поисковый ключ: NFC для хранения, очистка пробелов и управляющих символов, ключ NFKC + полный case folding + ё→е, версия правил ключа и переиндексация при её смене.

## ADDED Requirements

### Requirement: NAM-01 Хранение имени в NFC
Система SHALL хранить и возвращать `display_name`, `given_name`, `family_name` и `middle_name` в форме нормализации NFC (UAX #15). Регистр и диакритику, введённые пользователем, система MUST сохранять.
Трассировка: CUJ-02, CUJ-03; ADR-0009; D-009, D-011
Источник: docs/research/03 §2.1

#### Scenario: Разложенная «й»
- **WHEN** вводится имя «Йога», где «Й» передана как `И` + U+0306
- **THEN** сохраняется «Йога» с одной кодовой точкой U+0419 в начале

#### Scenario: Регистр сохраняется
- **WHEN** вводится имя «МакДоналд»
- **THEN** сохраняется и возвращается «МакДоналд» без изменения регистра

### Requirement: NAM-02 Обрезка и схлопывание пробелов
Перед сохранением система SHALL удалять символы со свойством Unicode White_Space по краям имени и заменять каждую внутреннюю последовательность таких символов одним U+0020. Символы без этого свойства (например, U+200B) MUST NOT считаться пробелами.
Трассировка: CUJ-02, CUJ-03; ADR-0009; D-011
Источник: docs/research/03 §2.4

#### Scenario: Разные пробелы
- **WHEN** вводится строка: U+00A0, пробел, «Анна», два символа TAB, «Мария», два пробела
- **THEN** сохраняется «Анна Мария»

#### Scenario: Пробел нулевой ширины
- **WHEN** вводится «Анна» + U+200B + «Мария»
- **THEN** U+200B не заменяется пробелом

### Requirement: NAM-03 Удаление управляющих символов
Перед сохранением система SHALL удалять из имени символы общей категории Cc, не имеющие свойства White_Space; остальные символы MUST сохраняться.
Трассировка: CUJ-03, CUJ-06; ADR-0009; D-011
Источник: docs/research/03 §2.4

#### Scenario: Символ BEL в имени
- **WHEN** вводится «Иван» + U+0007
- **THEN** сохраняется «Иван»

### Requirement: NAM-04 Запрет пустого имени
Если после очистки (NAM-02, NAM-03) `display_name` не содержит ни одного символа общих категорий L, M или N, система SHALL отклонять операцию с ошибкой `name.empty`.
Трассировка: CUJ-03, CUJ-06; ADR-0009; D-022
Источник: docs/research/03 §2.4

#### Scenario: Только пробелы
- **WHEN** `display_name` состоит из трёх пробелов
- **THEN** операция отклоняется с ошибкой `name.empty`

#### Scenario: Только пунктуация
- **WHEN** `display_name` = «—»
- **THEN** операция отклоняется с ошибкой `name.empty`

#### Scenario: Имя из цифр
- **WHEN** `display_name` = «007»
- **THEN** имя принимается

### Requirement: NAM-05 Построение ключа имени
Ключ имени SHALL строиться из очищенного имени в порядке: (1) NFKC; (2) полный Unicode default case folding — статусы C и F, без T; (3) замена каждой `ё` (U+0451) на `е` (U+0435). Других преобразований ключ MUST NOT содержать.
Трассировка: CUJ-02; ADR-0009; D-011
Источник: docs/research/03 §2.1–§2.3, §8.2

#### Scenario: Регистр и ё
- **WHEN** строятся ключи для «Семёнов», «СЕМЕНОВ» и «семенов»
- **THEN** все три ключа равны «семенов»

#### Scenario: Совместимые формы
- **WHEN** строится ключ для полноширинного «Ｉｖａｎ»
- **THEN** ключ равен «ivan»

### Requirement: NAM-06 Полный case folding без тюркских правил
Свёртка регистра SHALL применять полные отображения (статус F), которые могут удлинять строку, и MUST NOT применять тюркские отображения (статус T).
Трассировка: CUJ-02; ADR-0009; D-011
Источник: docs/research/03 §2.2

#### Scenario: Эсцет
- **WHEN** строятся ключи для «Straße» и «STRASSE»
- **THEN** оба ключа равны «strasse»

#### Scenario: Турецкая I
- **WHEN** строятся ключи для «ISTANBUL» и «ıstanbul»
- **THEN** первый ключ равен «istanbul», второй — «ıstanbul», ключи различаются

### Requirement: NAM-07 Без снятия диакритики
Кроме замены ё→е, ключ MUST сохранять диакритические знаки: имена, различающиеся только диакритикой, SHALL давать разные ключи.
Трассировка: CUJ-02; ADR-0009; D-011
Источник: docs/research/03 §2.3

#### Scenario: Буква «й»
- **WHEN** строятся ключи для «Йошкин» и «Иошкин»
- **THEN** ключи различаются

#### Scenario: Латинская диакритика
- **WHEN** строятся ключи для «José» и «Jose»
- **THEN** ключи различаются

#### Scenario: Буква «ё»
- **WHEN** строятся ключи для «Ёлкин» и «Елкин»
- **THEN** ключи равны «елкин»

### Requirement: NAM-08 Данные case folding Unicode 16.0
Отображения case folding SHALL браться из файла CaseFolding.txt базы символов Unicode версии 16.0; символы, не имеющие в нём отображения со статусом C или F, MUST оставаться без изменений.
Трассировка: CUJ-02; ADR-0006, ADR-0009; D-021
Источник: docs/research/03 §2.2

#### Scenario: Заглавная эсцет
- **WHEN** строится ключ для «ẞ» (U+1E9E)
- **THEN** ключ равен «ss»

#### Scenario: Символ без отображения
- **WHEN** строится ключ для «李»
- **THEN** ключ равен «李»

### Requirement: NAM-09 Версия правил ключа
Правила построения ключа SHALL иметь идентификатор версии, включающий версию данных Unicode. База данных MUST хранить версию правил, по которой построены её ключи имён.
Трассировка: CUJ-02, CUJ-08; ADR-0009; D-011
Источник: docs/research/03 §2.5

#### Scenario: Новая база
- **WHEN** создаётся новая база данных
- **THEN** в ней сохранена текущая версия правил ключа

### Requirement: NAM-10 Переиндексация при смене версии
При открытии базы, версия правил ключа которой отличается от текущей, система SHALL перестроить ключи имён всех контактов до начала обслуживания поиска по имени и MUST сообщать о неготовности до завершения [ПРЕДЛОЖЕНИЕ АГЕНТА: автоматически при запуске]. Ход переиндексации SHALL быть виден администратору.
Трассировка: CUJ-02, CUJ-07, CUJ-08; ADR-0009; D-011

#### Scenario: Обновление правил
- **WHEN** база с версией правил K1 открывается сборкой с версией K2
- **THEN** до окончания переиндексации система сообщает о неготовности
- **AND** после неё база хранит версию K2, а поиск использует ключи K2

### Requirement: NAM-11 Атомарность переиндексации
Переиндексация SHALL быть атомарной: поиск по имени видит либо все ключи старой версии, либо все ключи новой. Сбой во время переиндексации MUST приводить к её повтору при следующем запуске без потери и изменения контактов.
Трассировка: CUJ-02, CUJ-07; ADR-0003, ADR-0009; D-011, D-019

#### Scenario: Сбой посередине
- **WHEN** процесс аварийно завершается после перестроения половины ключей
- **THEN** после перезапуска база хранит прежнюю версию K1 и переиндексация начинается заново
- **AND** число контактов и их данные не изменились

### Requirement: NAM-12 Ключ поискового запроса
Строка запроса поиска по имени SHALL проходить ту же очистку (NAM-02, NAM-03) и построение ключа (NAM-05) текущей версии, что и хранимые имена.
Трассировка: CUJ-02; ADR-0009; D-011

#### Scenario: Запрос с пробелами и ё
- **WHEN** запрос поиска по имени равен «  СЕМЁН »
- **THEN** поиск выполняется по ключу «семен»
