# phone-normalization

## Purpose

Определяет, как BUDB превращает введённую строку телефона в каноническую форму E.164 с добавочным номером: шаги нормализации, регион по умолчанию, проверку возможности номера, понятные ошибки и версию правил.

## ADDED Requirements

### Requirement: PHN-01 Канонический результат нормализации
Результат нормализации SHALL состоять из `e164` — `+` и не более 15 цифр, первая из которых не 0, — необязательного `extension` из 1–10 цифр и `raw_input`, равного входной строке. Для хранения и поиска MUST использоваться только `e164` и `extension`.
Трассировка: CUJ-01, CUJ-03; ADR-0008; D-010, D-022
Источник: docs/research/03 §1.1, §1.2

#### Scenario: Национальный ввод
- **WHEN** вводится `8 (912) 345-67-89` при регионе RU
- **THEN** результат: `e164` = `+79123456789`, `extension` отсутствует, `raw_input` = `8 (912) 345-67-89`

### Requirement: PHN-02 Порядок шагов нормализации
Нормализация SHALL выполнять шаги строго по порядку: (1) NFKC; (2) обрезка пробельных символов по краям; (3) отделение добавочного номера (PHN-04); (4) удаление разделителей (PHN-03); (5) определение кода страны (PHN-05, PHN-06, PHN-09); (6) проверка длины (PHN-10, PHN-11). Ошибка на любом шаге MUST прекращать нормализацию.
Трассировка: CUJ-01, CUJ-03; ADR-0008; D-010
Источник: docs/research/03 §1.5 п. 1–3

#### Scenario: Полноширинные цифры
- **WHEN** вводится `＋７ (９１２) ３４５-６７-８９`
- **THEN** результат: `e164` = `+79123456789`

### Requirement: PHN-03 Разделители и недопустимые символы
Система SHALL удалять разделители: символы Unicode White_Space, `-`, `.`, `(`, `)`, `/`. Знак `+` допускается только первым символом. Любой другой символ, кроме цифр 0–9, MUST приводить к ошибке `phone.invalid_character`; текст вокруг номера (например, `Tel:`) не пропускается [ПРЕДЛОЖЕНИЕ АГЕНТА].
Трассировка: CUJ-03, CUJ-06; ADR-0008; D-010
Источник: docs/research/03 §1.5 п. 1, §2.4

#### Scenario: Смешанные разделители
- **WHEN** вводится `+7 (912) 345.67/89`
- **THEN** результат: `e164` = `+79123456789`

#### Scenario: Посторонний текст
- **WHEN** вводится `Tel: +7 912 3456789`
- **THEN** нормализация завершается ошибкой `phone.invalid_character`

#### Scenario: Плюс не в начале
- **WHEN** вводится `7+9123456789`
- **THEN** нормализация завершается ошибкой `phone.invalid_character`

### Requirement: PHN-04 Добавочный номер
Система SHALL распознавать добавочный номер по маркерам `;ext=`, `ext.`, `ext`, `x`, `доб.`, `#` без учёта регистра: цифры после первого маркера становятся `extension`. `extension` MUST содержать от 1 до 10 цифр (разделители PHN-03 удаляются); иначе нормализация завершается ошибкой `phone.invalid_extension`.
Трассировка: CUJ-03; ADR-0008; D-010, D-022
Источник: docs/research/03 §1.2, §1.5 п. 1

#### Scenario: Русский маркер
- **WHEN** вводится `+7 495 123-45-67 доб. 1234`
- **THEN** результат: `e164` = `+74951234567`, `extension` = `1234`

#### Scenario: Слишком длинный добавочный
- **WHEN** вводится `+7 495 123-45-67 ext 12345678901`
- **THEN** нормализация завершается ошибкой `phone.invalid_extension`

#### Scenario: Маркер без цифр
- **WHEN** вводится `+7 495 1234567 #`
- **THEN** нормализация завершается ошибкой `phone.invalid_extension`

### Requirement: PHN-05 Международная форма номера
Если номер начинается с `+`, система SHALL разбирать следующие цифры как код страны и национальный номер без учёта региона. Если номер начинается с международного префикса региона (для RU — `810` или `00`), система SHALL отбросить префикс и обработать остаток так же, как цифры после `+`.
Трассировка: CUJ-01, CUJ-03; ADR-0008; D-010
Источник: docs/research/03 §1.3, §1.4

#### Scenario: Номер с плюсом
- **WHEN** вводится `+44 20 7946 0958` при регионе RU
- **THEN** результат: `e164` = `+442079460958`

#### Scenario: Префикс 810
- **WHEN** вводится `8-10-44-20-7946-0958` при регионе RU
- **THEN** результат: `e164` = `+442079460958`

#### Scenario: Префикс 00
- **WHEN** вводится `0049 30 1234567` при регионе RU
- **THEN** результат: `e164` = `+49301234567`

### Requirement: PHN-06 Национальный формат региона RU
При регионе RU и отсутствии международной формы система SHALL преобразовывать: 11 цифр с первой `8` — в `+7` и последние 10 цифр; 11 цифр с первой `7` — в `+` и эти цифры [НЕ ПОДТВЕРЖДЕНО]; 10 цифр — в `+7` и эти цифры. Другое число цифр MUST приводить к ошибке `phone.invalid_length`.
Трассировка: CUJ-01, CUJ-03; ADR-0008; D-010
Источник: docs/research/03 §1.4

#### Scenario: Транковый префикс 8
- **WHEN** вводится `8 812 345-67-89` при регионе RU
- **THEN** результат: `e164` = `+78123456789`

#### Scenario: Десять цифр
- **WHEN** вводится `912 345 67 89` при регионе RU
- **THEN** результат: `e164` = `+79123456789`

#### Scenario: Неверное число цифр
- **WHEN** вводится `345-67-89` при регионе RU
- **THEN** нормализация завершается ошибкой `phone.invalid_length`

### Requirement: PHN-07 Регион по умолчанию
Регион по умолчанию SHALL задаваться конфигурацией (D-033), по умолчанию `RU`. В v1 MUST поддерживаться значения `RU` и `none` [ПРЕДЛОЖЕНИЕ АГЕНТА]; при `none` номер без международной формы отклоняется с ошибкой `phone.region_required`. Неизвестное значение MUST приводить к отказу запуска с ошибкой конфигурации.
Трассировка: CUJ-03, CUJ-06; ADR-0008, ADR-0017; D-010, D-033
Источник: docs/research/03 §1.5 п. 4

#### Scenario: Регион none
- **WHEN** регион по умолчанию `none` и вводится `8 912 345-67-89`
- **THEN** нормализация завершается ошибкой `phone.region_required`

#### Scenario: Неизвестный регион
- **WHEN** в конфигурации задан регион `XX`
- **THEN** система не запускается и сообщает об ошибке конфигурации региона

### Requirement: PHN-08 Регион операции
Создание и изменение контакта, импорт и поиск по телефону SHALL принимать необязательный регион из PHN-07, который заменяет регион по умолчанию только для этой операции [ПРЕДЛОЖЕНИЕ АГЕНТА].
Трассировка: CUJ-05, CUJ-06; ADR-0008; D-010
Источник: docs/research/03 §1.5 п. 4

#### Scenario: Переопределение на none
- **WHEN** регион по умолчанию `RU`, а операция передаёт регион `none` и номер `89123456789`
- **THEN** нормализация завершается ошибкой `phone.region_required`

### Requirement: PHN-09 Код страны по списку ITU
Код страны SHALL определяться как префикс из 1–3 цифр, входящий во встроенный список кодов, присвоенных ITU странам и глобальным сервисам (все страны). Если такого префикса нет, нормализация MUST завершаться ошибкой `phone.unknown_country_code`.
Трассировка: CUJ-03; ADR-0008; D-010
Источник: docs/research/03 §1.1, §1.5 п. 3

#### Scenario: Трёхзначный код
- **WHEN** вводится `+998 90 123 45 67`
- **THEN** результат: `e164` = `+998901234567`

#### Scenario: Неприсвоенный код
- **WHEN** вводится `+28 1234 5678` (коды 28x не присвоены [НЕ ПОДТВЕРЖДЕНО])
- **THEN** нормализация завершается ошибкой `phone.unknown_country_code`

### Requirement: PHN-10 Общая длина номера
Число цифр `e164` (код страны и национальный номер вместе) MUST быть не больше 15, а национальный номер — не короче 4 цифр [ПРЕДЛОЖЕНИЕ АГЕНТА]. Иначе нормализация SHALL завершаться ошибкой `phone.invalid_length`.
Трассировка: CUJ-03; ADR-0008; D-010
Источник: docs/research/03 §1.1

#### Scenario: Шестнадцать цифр
- **WHEN** вводится `+49 1234 5678 9012 34`
- **THEN** нормализация завершается ошибкой `phone.invalid_length`

#### Scenario: Короткий национальный номер
- **WHEN** вводится `+44 123`
- **THEN** нормализация завершается ошибкой `phone.invalid_length`

### Requirement: PHN-11 Национальные длины для кода +7
Для кода страны 7 национальный номер MUST содержать ровно 10 цифр, иначе — ошибка `phone.invalid_length`. Таблица национальных длин SHALL быть расширяемыми данными правил; для кодов без записи в ней действует только PHN-10.
Трассировка: CUJ-01, CUJ-03; ADR-0008; D-010
Источник: docs/research/03 §1.4

#### Scenario: Номер Казахстана
- **WHEN** вводится `+7 727 123 45 67`
- **THEN** результат: `e164` = `+77271234567`

#### Scenario: Девять цифр после +7
- **WHEN** вводится `+7 912 345 67 8`
- **THEN** нормализация завершается ошибкой `phone.invalid_length`

#### Scenario: Код без таблицы длин
- **WHEN** вводится `+49 30 1234567`
- **THEN** результат: `e164` = `+49301234567` (проверяется только PHN-10)

### Requirement: PHN-12 Сохранение исходного ввода
`raw_input` SHALL сохраняться точно в том виде, в каком получен, до любых шагов нормализации. Входная строка MUST быть не длиннее 64 кодовых точек [ПРЕДЛОЖЕНИЕ АГЕНТА]; более длинная отклоняется с ошибкой `phone.input_too_long`.
Трассировка: CUJ-03, CUJ-06; ADR-0008; D-009, D-010
Источник: docs/research/03 §1.2

#### Scenario: Ввод сохраняется как есть
- **WHEN** вводится ` 8 (912) 345-67-89 ` с пробелами по краям
- **THEN** `raw_input` равен ` 8 (912) 345-67-89 ` побайтово

#### Scenario: Слишком длинный ввод
- **WHEN** вводится строка из 65 символов
- **THEN** нормализация завершается ошибкой `phone.input_too_long`

### Requirement: PHN-13 Идемпотентность нормализации
Нормализация канонической формы SHALL давать тот же результат при любом регионе: `e164` переходит в тот же `e164`, а `e164;ext=N` — в тот же `e164` с `extension` = N. Повторная нормализация полученного `e164` MUST NOT менять его.
Трассировка: CUJ-05, CUJ-06; ADR-0008; D-010

#### Scenario: Повторная нормализация
- **WHEN** результат нормализации `8 (912) 345-67-89` при регионе RU (`+79123456789`) нормализуется снова при регионе `none`
- **THEN** результат: `e164` = `+79123456789`

#### Scenario: Каноническая форма с добавочным
- **WHEN** нормализуется `+74951234567;ext=101`
- **THEN** результат: `e164` = `+74951234567`, `extension` = `101`

### Requirement: PHN-14 Понятная ошибка нормализации
При отказе система SHALL возвращать машиночитаемый код из фиксированного набора `phone.empty`, `phone.invalid_character`, `phone.invalid_extension`, `phone.region_required`, `phone.unknown_country_code`, `phone.invalid_length`, `phone.input_too_long` [ПРЕДЛОЖЕНИЕ АГЕНТА] и описание причины на языке интерфейса. Номер с ошибкой MUST NOT сохраняться.
Трассировка: CUJ-03, CUJ-05, CUJ-06; ADR-0008, ADR-0010; D-010

#### Scenario: Пустой ввод
- **WHEN** вводится строка из одних пробелов
- **THEN** нормализация завершается ошибкой `phone.empty`

#### Scenario: Буквы вместо цифр
- **WHEN** вводится `abc`
- **THEN** нормализация завершается ошибкой `phone.invalid_character` с описанием недопустимого символа

### Requirement: PHN-15 Версия правил нормализации
Правила нормализации (шаги, список кодов ITU, таблицы регионов и длин) SHALL иметь идентификатор версии, доступный администратору. Для каждого телефона система MUST сохранять версию правил и регион, применённые при нормализации [ПРЕДЛОЖЕНИЕ АГЕНТА].
Трассировка: CUJ-03, CUJ-08; ADR-0008; D-010
Источник: docs/research/03 §1.2 п. 3

#### Scenario: Запись версии
- **WHEN** телефон `8 912 345-67-89` сохраняется при регионе RU и версии правил R1
- **THEN** у телефона сохранены версия R1 и регион RU

### Requirement: PHN-16 Повторная нормализация при смене правил
Повторная нормализация, запускаемая администратором (admin-cli), SHALL пересчитывать `e164` и `extension` из `raw_input` по текущей версии правил и сохранённому региону, увеличивая `version` изменённых контактов на 1 [ПРЕДЛОЖЕНИЕ АГЕНТА]. Телефоны, дающие ошибку по новым правилам, MUST оставаться без изменений и попадать в отчёт по `id` контакта.
Трассировка: CUJ-06, CUJ-08; ADR-0008; D-010
Источник: docs/research/03 §1.2 п. 3

#### Scenario: Номер стал недопустимым
- **WHEN** новая версия правил отвергает сохранённый `raw_input` контакта X
- **THEN** телефон контакта X остаётся прежним
- **AND** отчёт повторной нормализации содержит `id` контакта X и код ошибки
