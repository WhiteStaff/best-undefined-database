# web-ui

## Purpose
Визуальный веб-интерфейс BUDB для операторов, редакторов и администраторов: единый поиск при вводе, карточка контакта, создание и правка с обработкой конфликтов, корзина, импорт и экспорт, страница состояния, вход и выход. Здесь фиксируется поведение и доступность (WCAG 2.2 AA, ru/en); технология интерфейса описана в ADR-0016 (D-031). Все данные UI получает через http-api (API).

## ADDED Requirements

### Requirement: UI-01 Поставка без внешних ресурсов
Сервер SHALL отдавать все ресурсы UI (скрипты, стили, иконки, шрифты, каталоги сообщений) сам, из своего исполняемого файла. UI MUST NOT обращаться к CDN, внешним шрифтам и другим внешним источникам и SHALL полностью работать в сети без доступа в интернет.
Трассировка: CUJ-01, CUJ-02; ADR-0016; D-031
Источник: docs/research/03 §5.4

#### Scenario: Изолированная сеть
- **WHEN** UI открывается на машине без доступа в интернет
- **THEN** все страницы загружаются и работают полностью

#### Scenario: Сетевые запросы страницы
- **WHEN** проверка записывает все сетевые запросы при загрузке UI
- **THEN** все запросы адресованы источнику самого сервера BUDB

### Requirement: UI-02 Единое поле поиска при вводе
На главной странице SHALL быть одно поле поиска, которое отправляет запрос через 250 мс после последнего нажатия клавиши. UI MUST показывать результаты только последнего запроса и отменять или игнорировать ответы устаревших запросов.
Трассировка: CUJ-01, CUJ-02; ADR-0016; D-013, D-031
Источник: docs/research/03 §5.1 п. 1 (debounce 200–300 мс)

#### Scenario: Быстрый ввод
- **WHEN** пользователь печатает `Семён` без пауз длиннее 250 мс
- **THEN** UI отправляет один запрос `POST /api/v1/contacts:search` после окончания ввода

#### Scenario: Ответы пришли не по порядку
- **WHEN** ответ на запрос `Се` приходит после ответа на запрос `Сем`
- **THEN** UI продолжает показывать результаты для `Сем`

### Requirement: UI-03 Автоопределение номера или имени
UI SHALL считать ввод номером, если после удаления разделителей по phone-normalization (PHN) он состоит только из цифр с необязательным `+` в начале; иначе — именем. Выбранный тип MUST быть виден, и пользователь SHALL иметь возможность переключить его вручную. [ПРЕДЛОЖЕНИЕ АГЕНТА: правило определения]
Трассировка: CUJ-01, CUJ-02; ADR-0016; D-010, D-011
Источник: docs/research/03 §5.1 п. 1

#### Scenario: Ввод номера
- **WHEN** пользователь вводит `8 (916) 123-45`
- **THEN** UI ищет по префиксу телефона и показывает отметку «номер»

#### Scenario: Ввод имени
- **WHEN** пользователь вводит `Анна 2`
- **THEN** UI ищет по префиксу имени и показывает отметку «имя»

#### Scenario: Ручное переключение
- **WHEN** пользователь переключает тип на «имя» для ввода `112`
- **THEN** UI повторяет поиск по полю `name`

### Requirement: UI-04 Подсветка совпадений
В списке результатов UI SHALL выделять совпавшую часть имени или номера семантическим элементом выделения. Границы выделения MUST вычисляться по позициям в исходной строке, а сама строка вставляется только как текст.
Трассировка: CUJ-01, CUJ-02; ADR-0016; D-031
Источник: docs/research/03 §5.1 п. 2

#### Scenario: Префикс имени
- **WHEN** поиск `сем` находит контакт `Семёнов Пётр`
- **THEN** в результате выделены первые три буквы `Сем`

#### Scenario: Разметка в имени
- **WHEN** имя контакта содержит `<b>Анна</b>`
- **THEN** UI показывает эту строку буквально, а не жирным шрифтом

### Requirement: UI-05 Доступный combobox поиска
Поле поиска и список результатов SHALL реализовывать паттерн combobox по ARIA APG: стрелки вверх и вниз перемещают по вариантам, Enter открывает карточку, Esc закрывает список. Число найденных MUST объявляться сообщением о статусе без перевода фокуса.
Трассировка: CUJ-01, CUJ-02; ADR-0016; D-031
Источник: docs/research/03 §5.1 п. 3, §5.2 (4.1.3)

#### Scenario: Выбор с клавиатуры
- **WHEN** пользователь вводит запрос, дважды нажимает стрелку вниз и Enter
- **THEN** открывается карточка второго результата

#### Scenario: Объявление результата
- **WHEN** поиск вернул 3 контакта
- **THEN** экранный диктор слышит «Найдено 3 контакта», а фокус остаётся в поле

### Requirement: UI-06 Карточка контакта
Карточка SHALL показывать отображаемое имя, части имени, все телефоны с метками в форме E.164 и с добавочным номером, отметку основного номера и время изменения. Для каждого номера MUST быть кнопка «Копировать» и ссылка `tel:`.
Трассировка: CUJ-01, CUJ-02; ADR-0016; D-009
Источник: docs/research/03 §5.1 п. 4

#### Scenario: Копирование номера
- **WHEN** оператор нажимает «Копировать» у номера `+79161234567`
- **THEN** в буфер обмена попадает `+79161234567`, и UI объявляет «Скопировано»

#### Scenario: Номер с добавочным
- **WHEN** у телефона есть добавочный `12`
- **THEN** ссылка имеет вид `tel:+79161234567;ext=12`

### Requirement: UI-07 Форма создания и редактирования
Форма SHALL позволять добавлять и удалять телефоны (не больше 10) и выбирать метку. Ошибки 422 MUST показываться текстом у соответствующего поля по `pointer` и коду ошибки, а фокус переносится на первое ошибочное поле; введённые значения сохраняются.
Трассировка: CUJ-03; ADR-0016; D-022
Источник: docs/research/03 §5.1 п. 5, §5.2 (3.3.1, 3.3.3)

#### Scenario: Ошибка в телефоне
- **WHEN** сервер отвечает 422 с `pointer` = `/phones/1/raw_input`
- **THEN** у второго телефона появляется текст ошибки, и фокус переходит на это поле

#### Scenario: Лимит телефонов
- **WHEN** в форме уже 10 телефонов
- **THEN** кнопка «Добавить телефон» недоступна, и рядом объяснена причина

### Requirement: UI-08 Показ нормализованного номера
При вводе телефона форма SHALL показывать рядом нормализованную форму E.164, полученную от `POST /api/v1/phones:normalize`, или текст ошибки «номер невозможен». Окончательной MUST считаться нормализация, которую сервер вернул при сохранении.
Трассировка: CUJ-03; ADR-0008, ADR-0016; D-010

#### Scenario: Предпросмотр
- **WHEN** пользователь вводит `8 916 123 45 67`
- **THEN** рядом с полем появляется `+79161234567`

#### Scenario: Невозможный номер
- **WHEN** пользователь вводит `12`
- **THEN** рядом с полем появляется сообщение об ошибке, а не E.164

### Requirement: UI-09 Подтверждение сохранения
UI SHALL сообщать «Сохранено» только после ответа 201 или 200 и MUST сохранять введённые данные в форме при любой ошибке или обрыве связи. Создание контакта UI отправляет с `Idempotency-Key`, поэтому повтор после обрыва MUST NOT создавать дубликат.
Трассировка: CUJ-03; ADR-0016; D-019
Источник: docs/research/03 §4.5

#### Scenario: Обрыв связи
- **WHEN** соединение рвётся до получения ответа на создание
- **THEN** форма сохраняет ввод, а кнопка «Повторить» отправляет запрос с тем же `Idempotency-Key`

#### Scenario: Успешное сохранение
- **WHEN** сервер ответил 201
- **THEN** UI показывает «Сохранено», а поиск сразу находит новый контакт

### Requirement: UI-10 Обработка конфликта версий
При ответе 412 UI SHALL загрузить актуальную версию контакта и показать её рядом с вводом пользователя, выделив различия. Ввод пользователя MUST NOT теряться. Пользователь выбирает: сохранить свой вариант поверх новой версии (с её ETag) или принять актуальную версию.
Трассировка: CUJ-04; ADR-0016; D-009
Источник: docs/research/03 §5.1 п. 5

#### Scenario: Чужая правка
- **WHEN** при сохранении сервер отвечает 412
- **THEN** UI показывает обе версии и сохраняет ввод пользователя в форме

#### Scenario: Сохранить своё
- **WHEN** пользователь выбирает «Сохранить мой вариант»
- **THEN** UI отправляет `PUT` с ETag актуальной версии

### Requirement: UI-11 Удаление с возможностью отмены
Удаление SHALL переносить контакт в корзину и показывать уведомление с кнопкой «Отменить», доступной с клавиатуры и объявляемой как статус. Уведомление MUST оставаться, пока пользователь его не закроет или не выполнит другое действие, но не дольше окна отмены API (API).
Трассировка: CUJ-03; ADR-0012, ADR-0016; D-012
Источник: docs/research/03 §5.1 п. 6

#### Scenario: Отмена удаления
- **WHEN** пользователь удаляет контакт и нажимает «Отменить»
- **THEN** UI вызывает `POST /api/v1/contacts/{id}:undelete`, и контакт снова виден в поиске

#### Scenario: Уведомление не исчезает по таймеру
- **WHEN** пользователь не трогает уведомление 30 секунд
- **THEN** кнопка «Отменить» по-прежнему доступна

### Requirement: UI-12 Корзина для администратора
Admin SHALL видеть страницу корзины со списком удалённых контактов, датой удаления и датой автоматической очистки, с действиями «Восстановить» и «Очистить сейчас». Очистка MUST требовать подтверждения в диалоге с именем контакта и предупреждением о необратимости.
Трассировка: CUJ-09; ADR-0012, ADR-0016; D-012
Источник: docs/research/03 §5.2 (3.3.4)

#### Scenario: Очистка с подтверждением
- **WHEN** admin нажимает «Очистить сейчас» и подтверждает в диалоге
- **THEN** UI вызывает `:purge` и показывает номер квитанции `purge_id`

#### Scenario: Отказ от очистки
- **WHEN** admin закрывает диалог подтверждения
- **THEN** запрос purge не отправляется

### Requirement: UI-13 Импорт с пробным прогоном
Страница импорта SHALL принимать файл через кнопку выбора, а не только перетаскиванием, и по умолчанию сначала выполнять пробный прогон (dry-run). UI MUST показывать прогресс и отчёт со счётчиками и ошибками по строкам, давать скачать отчёт и только затем предлагать «Импортировать».
Трассировка: CUJ-06; ADR-0016; D-016
Источник: docs/research/03 §5.1 п. 7, §5.2 (2.5.7)

#### Scenario: Пробный прогон
- **WHEN** writer выбирает CSV-файл с двумя ошибочными строками
- **THEN** UI показывает отчёт dry-run с номерами этих строк, и данные не меняются

#### Scenario: Подтверждение импорта
- **WHEN** после отчёта пользователь нажимает «Импортировать»
- **THEN** UI создаёт задачу импорта без `dry_run` и показывает её прогресс

### Requirement: UI-14 Экспорт
Admin SHALL запускать экспорт со страницы экспорта, выбрав формат CSV или NDJSON. UI MUST показывать состояние задачи и ссылку на скачивание, когда файл готов, и предупреждать, что файл содержит персональные данные.
Трассировка: CUJ-06; ADR-0016; D-016

#### Scenario: Готовый экспорт
- **WHEN** задача экспорта завершилась
- **THEN** UI показывает ссылку «Скачать» на `GET /api/v1/jobs/{id}/result`

#### Scenario: Роль writer
- **WHEN** writer открывает UI
- **THEN** пункт «Экспорт» не показывается

### Requirement: UI-15 Страница состояния БД
Admin SHALL видеть страницу состояния с данными `GET /api/v1/admin/status`: число контактов, число в корзине, размер хранилища, готовность, время последнего бэкапа и проверки целостности, срок хранения корзины. Значения MUST обновляться не реже раза в 15 секунд, пока страница открыта.
Трассировка: CUJ-07, CUJ-08; ADR-0016; D-025
Источник: docs/research/03 §5.1 п. 8, §7.4 (CUJ-8)

#### Scenario: Просмотр состояния
- **WHEN** admin открывает страницу состояния
- **THEN** UI показывает время последнего бэкапа и результат последней проверки

#### Scenario: Reader
- **WHEN** reader пытается открыть страницу состояния по адресу
- **THEN** UI показывает сообщение «Недостаточно прав»

### Requirement: UI-16 Вход и выход
Форма входа SHALL принимать логин и пароль, разрешать вставку и автозаполнение менеджером паролей и MUST NOT содержать тестов на память, капчи или требования переписать символы. Кнопка «Выйти» доступна на каждой странице и завершает сессию по access-control (ACL).
Трассировка: CUJ-10; ADR-0011, ADR-0016; D-015
Источник: docs/research/03 §5.1 п. 9, §5.2 (3.3.8)

#### Scenario: Вставка пароля
- **WHEN** пользователь вставляет пароль из менеджера паролей
- **THEN** поле принимает вставку, и вход выполняется

#### Scenario: Выход
- **WHEN** пользователь нажимает «Выйти»
- **THEN** UI показывает форму входа, а кнопка браузера «Назад» не открывает данные контактов

### Requirement: UI-17 Истечение сессии без потери ввода
Если во время работы API отвечает 401, UI SHALL показать форму повторного входа поверх текущей страницы и MUST сохранить несохранённый ввод формы, чтобы после входа его можно было отправить. [ПРЕДЛОЖЕНИЕ АГЕНТА]
Трассировка: CUJ-03; ADR-0016; D-015

#### Scenario: Сессия истекла при редактировании
- **WHEN** пользователь нажимает «Сохранить» после 31 минуты бездействия
- **THEN** UI просит войти снова, а после входа форма содержит прежний ввод

### Requirement: UI-18 Действия по роли
UI SHALL показывать только действия, доступные роли пользователя: reader не видит кнопок изменения, writer — корзины, экспорта и состояния. Скрытие кнопок MUST NOT заменять проверку прав на сервере.
Трассировка: CUJ-10; ADR-0011, ADR-0016; D-015

#### Scenario: Reader в карточке
- **WHEN** reader открывает карточку контакта
- **THEN** кнопок «Изменить» и «Удалить» нет

### Requirement: UI-19 Контраст и перестроение
UI SHALL соответствовать WCAG 2.2 AA по контрасту: текст не меньше 4.5:1, крупный текст, компоненты и индикатор фокуса не меньше 3:1. При ширине окна 320 CSS px UI MUST работать без горизонтальной прокрутки.
Трассировка: CUJ-01, CUJ-02; ADR-0016; D-031
Источник: docs/research/03 §5.2 (1.4.3, 1.4.10, 1.4.11)

#### Scenario: Автоматическая проверка контраста
- **WHEN** проверка доступности анализирует все страницы UI
- **THEN** нарушений критериев 1.4.3 и 1.4.11 не найдено

#### Scenario: Узкий экран
- **WHEN** ширина окна 320 CSS px
- **THEN** поиск и карточка помещаются без горизонтальной прокрутки

### Requirement: UI-20 Клавиатура и видимый фокус
Все функции UI SHALL быть доступны с клавиатуры в логичном порядке фокуса. Индикатор фокуса MUST быть видим всегда и не закрываться полностью липкими панелями и уведомлениями.
Трассировка: CUJ-01, CUJ-03; ADR-0016; D-031
Источник: docs/research/03 §5.2 (2.1.1, 2.4.3, 2.4.7, 2.4.11)

#### Scenario: Работа без мыши
- **WHEN** пользователь находит контакт, правит его и сохраняет только клавиатурой
- **THEN** все шаги выполняются, а фокус виден на каждом элементе

#### Scenario: Липкая шапка
- **WHEN** фокус переходит на элемент под липкой шапкой
- **THEN** страница прокручивается так, что элемент виден

### Requirement: UI-21 Размер целей нажатия
Каждая интерактивная цель SHALL иметь размер не меньше 24×24 CSS px или достаточный отступ от соседних целей по WCAG 2.2 (2.5.8). Это MUST проверяться автоматически для всех страниц.
Трассировка: CUJ-01; ADR-0016; D-031
Источник: docs/research/03 §5.2 (2.5.8)

#### Scenario: Кнопка копирования
- **WHEN** проверка измеряет кнопку «Копировать» в карточке
- **THEN** её размер не меньше 24×24 CSS px

### Requirement: UI-22 Локализация ru/en
UI SHALL поддерживать русский и английский: язык выбирается по `Accept-Language`, переключается вручную и запоминается; атрибут языка страницы MUST соответствовать выбору. Числа с существительными MUST склоняться по правилам множественного числа CLDR: ru — one/few/many/other, en — one/other.
Трассировка: CUJ-01, CUJ-02; ADR-0016; D-031
Источник: docs/research/03 §5.3

#### Scenario: Плюралы ru
- **WHEN** найдено 1, 2 и 5 контактов в интерфейсе на русском
- **THEN** UI пишет «1 контакт», «2 контакта» и «5 контактов»

#### Scenario: Плюралы en
- **WHEN** найден 1 контакт в интерфейсе на английском
- **THEN** UI пишет «1 contact», а для 2 — «2 contacts»

### Requirement: UI-23 Мягкая деградация при 503 и 429
При ответе 503 или 429 UI SHALL показывать ненавязчивое сообщение со временем повтора из `Retry-After`, сохранять ввод и MUST повторять поиск автоматически один раз по истечении `Retry-After`. Изменения данных UI автоматически не повторяет, а предлагает кнопку «Повторить».
Трассировка: CUJ-01, CUJ-03, CUJ-08; ADR-0016; D-032
Источник: docs/research/03 §4.6

#### Scenario: Перегрузка при поиске
- **WHEN** поиск получает 503 с `Retry-After: 2`
- **THEN** UI показывает «Сервис перегружен, повтор через 2 с» и через 2 с повторяет поиск

#### Scenario: Перегрузка при сохранении
- **WHEN** сохранение получает 503
- **THEN** форма сохраняет ввод и показывает кнопку «Повторить»
