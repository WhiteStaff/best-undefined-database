## Вердикт

**Не готово к архивированию и к реализации фаз 7, 10, 11, 14 без правок.** Ядро движка (COW B+tree, протокол коммита, правило переиспользования §3.1, fail-stop) продумано хорошо и проверяемо. Блокируют два места:

- главный путь CUJ-01 в UI для российского ввода номера (GF2-01);
- повторная выдача `id` после restore в сочетании с журналом purge по `contact_id` (GF2-02).

До задачи 0.1 нужно:

1. Расширить таблицу design.md и задачу 0.1 пятнадцатью противоречиями из раздела выше.
2. Закрыть дыры purge: затирание на простаивающей системе, состояния при сбое, разделители, полнота теста (GF2-08…GF2-11).
3. Закрыть отказы и последствия restore: порча, полный диск, часы, учётные записи после restore (GF2-12…GF2-16).
4. Задать RPO, расписание бэкапов и HTTP-отображение «исход неизвестен» (GF2-17, GF2-18).
5. Выбросить или отложить лишнее из GF2-49…GF2-51.
