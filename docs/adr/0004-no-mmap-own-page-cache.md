# 0004. Без mmap: явный pread/pwrite и собственный кэш страниц

## Status

Accepted, 2026-10-24. Решение D-018 (пункт «mmap не используется»), D-021 (memmap2 запрещён).

## Context and Problem Statement

Движок — COW B+tree со страницами 4 KiB (ADR 0003). LMDB, bbolt и redb читают страницы через отображение файла в память (docs/research/02, §1). Требование fail-stop (ADR 0005) обязывает видеть каждую ошибку ввода-вывода как код возврата, а запрет `unsafe` (ADR 0002) ограничивает приёмы работы с памятью.

Как движок читает и пишет страницы: через mmap или через явные системные вызовы и собственный кэш?

## Decision Drivers

* Ошибки I/O должны приходить кодом возврата, чтобы сработал fail-stop (D-019).
* Контроль над вытеснением и над тем, что и когда попадает на диск.
* Запрет `unsafe` во всех крейтах (D-020).
* Предсказуемая память: внутренние узлы около 155 МБ при 10^8 записей, кэш по умолчанию 512 МБ (docs/research/02, §7.2).

## Considered Options

1. **mmap только для чтения + `pwrite` для записи** (схема LMDB/bbolt).
2. **mmap для чтения и записи.**
3. **Явный `pread`/`pwrite` + собственный кэш страниц** — выбрано.
4. **Direct I/O (`O_DIRECT`) + собственный кэш** в обход кэша ОС.

## Decision Outcome

Выбран вариант 3 (D-018): только `pread`/`pwrite` (на Windows — эквиваленты через std или `windows-sys`) и собственный кэш страниц в процессе. Крейт `memmap2` запрещён политикой зависимостей (D-021, ADR 0006).

Обоснование:

* CIDR 2022: mmap «not a suitable replacement for a traditional buffer pool» (docs/research/02, §2.4 п. 1, [S56]).
* При mmap ошибки ввода-вывода приходят сигналами (SIGBUS), а не кодами возврата; это противоречит fail-stop (docs/research/02, §2.4 п. 1, оценка исследователя).
* Без mmap достижим `#![forbid(unsafe_code)]` (docs/research/02, §5.3).
* Страница проверяется по CRC32C при загрузке в кэш (docs/research/02, §2.4 п. 3), то есть каждое чтение с диска проходит одну точку проверки `[ДОПУЩЕНИЕ]`.

Параметры кэша: размер по умолчанию 512 МБ, настраивается (docs/research/02, §7.2) `[ПРЕДЛОЖЕНИЕ АГЕНТА]` — значение по умолчанию в журнале решений не зафиксировано. Политика вытеснения в этом ADR не выбирается и описывается в `design.md` `[ПРЕДЛОЖЕНИЕ АГЕНТА]`.

### Consequences

* Good, потому что каждая ошибка I/O видна как результат вызова и обрабатывается по правилу fail-stop.
* Good, потому что объём памяти процесса ограничен настройкой кэша, а не поведением ОС.
* Good, потому что весь I/O проходит через один интерфейс; его можно заменить симулятором диска в тестах (ADR 0015).
* Bad, потому что приходится писать и тестировать кэш страниц и вытеснение самим.
* Bad, потому что данные кэшируются дважды: в кэше ОС и в нашем (Direct I/O отклонён) `[ДОПУЩЕНИЕ]`.
* Bad, потому что каждое чтение страницы — копия в буфер процесса, в отличие от нулевого копирования mmap `[ДОПУЩЕНИЕ]`.

### Confirmation

* cargo-deny с allowlist отвергает `memmap2` и любые крейты отображения файлов (ADR 0006).
* Ревью и поиск по исходникам: нет вызовов `mmap`/`MapViewOfFile`; `unsafe` запрещён (ADR 0002).
* Тест внедрения сбоев: EIO на `pread` приводит к явной ошибке, а не к падению процесса по сигналу (ADR 0015).
* Бенчмарк на эталонном стенде подтверждает SLO точного поиска p99 ≤ 2 мс на прогретом кэше и ≤ 10 мс на холодном (D-024).

## Pros and Cons of the Options

### mmap только для чтения

* Good: нулевое копирование, проверенная схема LMDB/bbolt (docs/research/02, §1).
* Bad: ошибки I/O сигналами; ОС управляет вытеснением (docs/research/02, §2.4, [S56]).

### mmap для чтения и записи

* Good: минимум кода.
* Bad: ОС сама решает, когда сбрасывать грязные страницы, что ломает порядок протокола коммита `[ДОПУЩЕНИЕ]`; те же проблемы, что в варианте 1.

### pread/pwrite + свой кэш

* Good: ошибки кодом возврата, контроль памяти, совместимость с `forbid(unsafe_code)`.
* Bad: больше кода.

### Direct I/O + свой кэш

* Good: нет двойного кэширования.
* Bad: требует выравненных буферов и платформенных флагов; на Windows аналог — `FILE_FLAG_NO_BUFFERING` (docs/research/02, §3.3, [S17]); выигрыш для ДЗ не обоснован исследованием `[ДОПУЩЕНИЕ]`.
