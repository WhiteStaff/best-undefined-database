# ADR — журнал архитектурных решений BUDB

Формат — MADR 4.0, статусы — по Nygard: `proposed`, `accepted`, `deprecated`, `superseded` (D-005, ADR 0001). Принятый ADR не переписывается: изменение решения оформляется новым ADR, а старый получает статус `superseded by NNNN`. Номера не переиспользуются.

Соглашения:

* Имя файла — `NNNN-kebab-title.md`, слаг латиницей; текст на русском.
* Заголовки секций MADR оставлены по-английски (`Context and Problem Statement`, `Decision Drivers`, `Considered Options`, `Decision Outcome`, `Consequences`, `Confirmation`, `Pros and Cons of the Options`, `More Information`), как структурные заголовки OpenSpec.
* Каждый ADR ссылается на решение оркестратора `D-NNN` из `docs/orchestrator-decisions.md`.
* Факты — со ссылкой на `docs/research/0N` (раздел) и URL источника. Пометки: `[ДОПУЩЕНИЕ]` — допущение автора; `[НЕ ПОДТВЕРЖДЕНО]` — не проверено по первоисточнику; `[ПРЕДЛОЖЕНИЕ АГЕНТА]` — то, чего нет в журнале решений; ждёт решения оркестратора.

## ВОПРОСЫ К ОРКЕСТРАТОРУ

Вопросы, которые открыли ADR 0001–0017 и `docs/cuj.md`. До ответа в текстах действует вариант, помеченный `[ПРЕДЛОЖЕНИЕ АГЕНТА]`. Оркестратор ответил решениями D-034…D-060 (`docs/orchestrator-decisions.md`); у каждого вопроса указано, какими решениями он закрыт. Спецификации по этим решениям исправит редактор после ревью; принятые ADR по D-005 не переписываются.

1. **Хранение служебных данных** (ADR 0011, 0012, 0013). D-018 называет три дерева. Где хранятся пользователи, хеши токенов, сессии, корзина, журнал аудита, ключи идемпотентности и задачи импорта? Где журнал очисток, чтобы он пережил потерю основного файла и применился при restore?
   **Закрыт частично:** D-055 (служебные деревья `users`, `api_tokens`, `idempotency_keys`, `trash_idx` в том же файле; UI-сессии в памяти; журнал аудита и журнал purge — отдельные файлы), D-036 и D-042 (журнал purge: отдельный файл со сбросом на устройство, копии в каждом бэкапе и в каталоге бэкапов, без хэшей). Где хранятся задачи импорта, решения не говорят.
2. **Purge и снимки** (ADR 0012). Перезапись невозможна, пока страницу видит живой снимок, идущий бэкап или вторая мета-страница. Что делает «очистить сейчас»: ждёт, прерывает снимок или отказывает? Что такое «сегменты журнала» в движке без WAL? Какой срок T_purge (в cuj.md предложено 24 ч)? Как сделать автоочистку не позже 30 дней при сроке корзины 30?
   **Закрыт:** D-056 (принудительный коммит N+1, затирание нулями после ухода читателей, T_purge = 24 ч, более долгие снимки завершаются принудительно, «сегменты журнала» неприменимы), D-049 (корзина 1…29 дней плюс не больше 24 ч до purge, в сумме ≤ 30 дней).
3. **Лимит длительности читателя и бэкап** (ADR 0003, 0013). Исследование предлагает около 30 с, бэкап 25 ГБ дольше. Нужно ли исключение для бэкапа? Каков срок хранения бэкапов (исследование предлагает ≤ 6 мес.)?
   **Закрыт:** D-056 (снимки бэкапа, экспорта и проверки освобождены от лимита 30 с, но ограничены T_purge), D-048 (лимит 30 с остаётся для интерактивных операций), D-037 (бэкапы: по умолчанию 30 дней, не больше 180).
4. **Admin CLI и эксклюзивная блокировка** (ADR 0013, 0017). Предложено так: онлайн-операции идут через admin-API сервера, офлайн-операции — напрямую по файлу.
   **Закрыт:** D-055 (онлайн-операции — через admin API, офлайн — по файлу под эксклюзивной блокировкой), D-046 (онлайн-эндпоинты администратора).
5. **Поведение после fail-stop** (ADR 0005): только чтение или завершение процесса? Предложено: перестать принимать записи, `/readyz` = не готов, затем выйти с ненулевым кодом.
   **Закрыт:** D-034 (отказ текущим записям, 503 не дольше 5 с, затем выход с отдельным кодом; чтения из памяти не обслуживаются).
6. **Формат `id`** (ADR 0007): неперечисляемый 128-битный (ULID/UUIDv7, исследование 03) или u64 (расчёты исследования 02)?
   **Закрыт:** D-057 (u64, монотонный, не переиспользуется; в JSON — десятичная строка).
7. **Версия Unicode** (ADR 0009): D-021 закрепляет `CaseFolding.txt` 16.0, исследование 03 цитирует 18.0.0. Как согласовать с таблицами `unicode-normalization`? Делать ли NFKC повторно после case folding? Нужны ли обрезка и схлопывание `White_Space`, поиск по началу каждого слова, индексация частей имени, минимальная длина префикса?
   **Закрыт:** D-050 (ключ = NFKC_Casefold, затем ё→е; отдельная повторная NFKC не нужна), D-058 (одна версия Unicode — новейшая в закреплённом `unicode-normalization`, ≥ 16.0; обрезка и схлопывание `White_Space`; минимальный префикс имени — 1 кодовая точка), D-051 (префикс каждого слова; части имени не индексируются), D-039 (генерация таблицы при сборке).
8. **Телефоны** (ADR 0008): нормализуется ли `7XXXXXXXXXX` (11 цифр без `+`) и 10 цифр в `+7`? Как нормализуется префикс для префиксного поиска («8916» → «+7916»)? Какую версию списка кодов ITU берём? Какой набор маркеров добавочного номера? Уникальна ли пара `(e164, extension)` в контакте, и может ли у контакта быть только один `is_primary`?
   **Закрыт частично:** D-052 (регионы RU и `none`; `7XXXXXXXXXX` — `[ДОПУЩЕНИЕ]`), D-059 (10 цифр → `+7`; список ITU по дате Operational Bulletin; пара `(e164, extension)` уникальна; ровно один `is_primary`). Не решены: нормализация префикса для префиксного поиска («8916» → «+7916») и набор маркеров добавочного номера.
9. **Детали API** (ADR 0010): утвердить OpenAPI 3.1, RFC 9457, ETag/If-Match с кодами 412/428, AIP-158, `Idempotency-Key`, асинхронный импорт, `/livez`, `/readyz`, `/metrics`. Разделение 503 и 429 (ADR 0017): предложено 503 при переполнении очереди движка, 429 по лимиту клиента.
   **Закрыт:** D-059 (OpenAPI 3.1, RFC 9457, 412/428, keyset по AIP-158, `Idempotency-Key`; 503 — перегрузка или неготовность, 429 — лимит клиента), D-044 (`urn:budb:problem:<code>`), D-047 и D-048 (страница 20/100, курсор 24 ч), D-053 (импорт без возобновления), D-046 (онлайн-эндпоинты администратора).
10. **Allowlist** (ADR 0006, 0011, 0015): транзитивные зависимости; `tower`, `tower-http`, `tracing-subscriber`, `thiserror`, `proptest-state-machine`, `tempfile`, `criterion`; крейты для SHA-256 токенов, CSPRNG и HMAC курсоров.
   **Закрыт частично:** D-060 (allowlist — прямые зависимости, denylist — весь транзитивный граф; `proptest-state-machine`, `sha2`, `hmac`, `getrandom`/`rand_core`), D-038 (`tower`, `tower-http`, `tracing-subscriber`, `thiserror`). Не решены: `tempfile` и `criterion`.
11. **Сборка TypeScript** (ADR 0016): `tsc` закреплённой версии без бандлера? Как проверять npm-цепочку? Какие минимальные версии браузеров?
   **Закрыт:** D-060 (закреплённый `tsc`, нативные ES-модули без бандлера, npm lock-файл с integrity; две последние версии Chrome, Edge, Firefox, Safari).
12. **Числа SLO вне D-024** (`docs/cuj.md`): окно 28 дней; доступность 99,9 %; UI ≤ 1 с; импорт ≥ 500 записей/с; RTO restore для 10^7 записей; точность `/readyz` 99,9 %; quickstart ≤ 15 мин; матрица прав по ролям; параметры сессии (idle и абсолютный таймауты); версии TLS.
   **Закрыт частично:** D-060 (SLO из `docs/cuj.md` утверждены: окно 28 дней, доступность 99,9 %). Явно не решены: RTO восстановления для 10^7 записей (в `docs/cuj.md` не выбрано), матрица прав по ролям (права на корзину меняет D-041), параметры сессии и версии TLS (в спецификациях остаются `[ПРЕДЛОЖЕНИЕ АГЕНТА]`).
13. **CSV-инъекция при экспорте** (`docs/cuj.md`, CUJ-06): экранировать ячейки, начинающиеся с `=+-@`, при том что номера начинаются с `+7`?
   **Закрыт:** D-060 (экранирование «+7…» при экспорте и снятие экранирования при обратном импорте).
