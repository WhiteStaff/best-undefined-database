# Глоссарий BUDB

Термины предметной области, движка хранения и процесса. Если термин опирается на внешний источник, указан раздел `docs/research/0N`; на решение оркестратора — `D-NNN`; на архитектурное решение — `ADR NNNN`. Термины внутри групп упорядочены по алфавиту.

## Предметная область

| Термин | Определение |
|---|---|
| **Возможные дубликаты** | Подсказка системы: новый или изменённый контакт похож на существующий. Дубликаты разрешены; слияние (merge) — в v2 (D-009). Критерий «похожести» не утверждён (ADR 0007). |
| **Возможный номер** (possible number) | Номер, который проходит проверку формата: код страны входит в список ITU, всего не больше 15 цифр, а для `+7` совпадает национальная длина (D-010). Не означает, что номер существует или выдан оператору. Аналог `isPossibleNumber` в libphonenumber, который проверяет только длину (docs/research/03, §1.3). |
| **Валидный номер** (valid number) | Номер из диапазона, который выдают операторы (аналог `isValidNumber`, docs/research/03, §1.3). Проверка валидности — вне скоупа v1 (D-010). |
| **Добавочный номер** (extension) | Цифры после основного номера (`доб.`, `ext`, `x`, `;ext=`), хранятся отдельно от `e164`; не больше 10 цифр (D-022; RFC 3966, docs/research/03, §1.2). |
| **Исходный ввод** (`raw_input`) | Строка телефона, как её ввёл пользователь; хранится для аудита и повторной нормализации при смене правил (D-009; docs/research/03, §1.2). |
| **Код страны** (CC) | 1–3 цифры в начале номера E.164; список ведёт ITU (docs/research/03, §1.1). |
| **Контакт** (Contact) | Агрегат модели данных: `id`, `display_name`, необязательные части имени, список телефонов (0..10), `version`, `created`/`updated` (D-009, D-022, ADR 0007). Идентичность задаёт только `id`. |
| **Корзина** (trash) | Состояние контакта после DELETE: контакт можно восстановить до истечения срока хранения (по умолчанию 7 дней, не больше 30), затем он очищается автоматически (D-012, ADR 0012). |
| **Метка телефона** (label) | Тип телефона в контакте: `mobile`, `home`, `work`, `other` (D-009). |
| **Нормализация телефона** | Преобразование ввода в E.164: NFKC, удаление разделителей, разбор `+`/`00`/`810`, регион по умолчанию (D-010, ADR 0008). |
| **Основной телефон** (`is_primary`) | Признак предпочтительного номера контакта (D-009). |
| **Отображаемое имя** (display name, `display_name`) | Обязательное имя контакта одной строкой, как ввёл пользователь, в NFC; 1–256 кодовых точек, не больше 1024 байт UTF-8 (D-009, D-022). Аналог `FN` в vCard (docs/research/03, §2.6). |
| **Очистка** (purge) | Необратимое уничтожение данных контакта: автоматически из корзины по сроку или командой администратора «очистить сейчас» по запросу субъекта, с физической перезаписью освобождённых страниц (D-012, ADR 0012). Соответствует «уничтожению» по 152-ФЗ, ст. 3 п. 8 (docs/research/03, §6.5). |
| **Персональные данные (ПДн)** | Любая информация, относящаяся к прямо или косвенно определённому физическому лицу (152-ФЗ, ст. 3 п. 1). Имя и телефон — ПДн (docs/research/03, §6.5). |
| **Поисковый ключ имени** | Строка, по которой индексируется и ищется имя: NFKC → полный default case folding (C+F, без тюркских правил) → ё→е; порядок бинарный; правила версионируются (D-011, ADR 0009). |
| **Регион по умолчанию** | Настройка, по которой разбираются номера в национальном формате; по умолчанию RU (`8XXXXXXXXXX` → `+7XXXXXXXXXX`) (D-010). |
| **Субъект ПДн** | Физическое лицо, к которому относятся персональные данные; может потребовать их уничтожения (docs/research/03, §6.5). |
| **Телефонная книга** | Совокупность контактов одного экземпляра BUDB; на экземпляр одна книга, мультиарендности нет (D-014). |
| **Транковый префикс** | Цифра национального междугороднего набора (в РФ — `8`), которая отбрасывается при переводе в E.164 (docs/research/03, §1.4). |
| **Части имени** | Необязательные `given_name`, `family_name`, `middle_name`, до 128 кодовых точек каждая; для идентичности не используются (D-022; docs/research/03, §2.6). |
| **Case folding** (свёртка регистра) | Отображение символов для регистронезависимого сравнения по `CaseFolding.txt`; полное свёртывание = статусы C+F (`ß` → `ss`) (docs/research/03, §2.2). Отличается от lowercase. |
| **E.164** | План нумерации ITU-T: только цифры, не больше 15, код страны 1–3 цифры; каноническая запись `+<CC><NSN>` (docs/research/03, §1.1). В BUDB телефоны хранятся строго в E.164 (D-022). |
| **IDD** (международный префикс) | Префикс выхода на международную связь: `810` в РФ, `00` во многих странах, `011` в NANP (docs/research/03, §1.3–§1.5). |
| **NFC / NFKC** | Формы нормализации Unicode (UAX #15): NFC — каноническая композиция, используется для хранения имени; NFKC — с эквивалентностью совместимости (`ﬁ` → `fi`, полноширинные цифры → ASCII), используется для ключа поиска и разбора телефона (docs/research/03, §2.1). |
| **NSN** | Национальный значимый номер: часть E.164 после кода страны (docs/research/03, §1.1). |

## Движок хранения

| Термин | Определение |
|---|---|
| **Верификатор / проверка целостности** | Офлайн- или онлайн-проверка: CRC32C всех страниц, упорядоченность ключей, согласованность трёх деревьев, учёт freelist (D-025; docs/research/02, §4; ADR 0013). |
| **Группа коммитов** (group commit) | Писатель собирает пачку операций из очереди, фиксирует её одной транзакцией и одним набором fsync и только потом подтверждает всем клиентам пачки (D-018; docs/research/02, §3.7; ADR 0005). |
| **Долговечность** (durability) | Подтверждённая запись переживает сбой процесса и потерю питания; подтверждение — только после цепочки fsync (D-019, ADR 0005). Как SLI — доля записанного, что затем успешно читается (docs/research/03, §7.1). |
| **Журнал аудита** | Журнал операций и событий безопасности: кто, когда, что, над каким `id`, результат; не содержит значений ПДн (D-012; 152-ФЗ, ст. 19 ч. 2 п. 8, docs/research/03, §6.5). |
| **Журнал очисток** (purge journal) | Список идентификаторов очищенных контактов без ПДн; повторно применяется при восстановлении из бэкапа, чтобы данные не «воскресли» (D-012). |
| **Кэш страниц** | Собственный кэш страниц в памяти процесса; заменяет mmap (D-018, ADR 0004). |
| **Мета-страница** | Одна из двух служебных страниц файла: magic, версия формата, размер страницы, txid, корни деревьев и freelist, CRC32C. При открытии выбирается валидная с наибольшим txid; писатель перезаписывает более старую (D-018; docs/research/02, §2.4 п. 2). |
| **Повреждение** (corruption) | Несовпадение контрольной суммы на странице, достижимой из валидной мета-страницы. В отличие от незавершённого коммита, сообщается явной ошибкой и никогда не откатывается молча (D-019; FAST'17, docs/research/02, §3.6). |
| **Порванная запись** (torn write) | Частично записанная страница после обрыва питания; запись сектора или страницы не считается атомарной (docs/research/02, §3.5). |
| **Поток-писатель** | Единственный поток, который выполняет транзакции записи и протокол коммита (D-032, ADR 0017). |
| **Протокол коммита (2PC)** | Последовательность: запись страниц → fsync → запись мета-страницы → fsync (D-019; docs/research/02, §2.4 п. 4). |
| **Снимок** (snapshot) | Неизменяемое состояние базы на конкретном txid: корень дерева, который видит читатель или бэкап (D-018, D-025). |
| **Теневая страничная адресация** (shadow paging) | Изменённые страницы пишутся в новое место, старые не трогаются до тех пор, пока их видит хотя бы один читатель (D-018; docs/research/02, §2.1 (c)). |
| **Три дерева** | `primary(id)`, `name_idx(key‖id)`, `phone_idx(digits‖id)` в одном файле, меняются одной атомарной транзакцией (D-018, ADR 0003). |
| **Уплотнение** (compaction) | Офлайн-копирование живого дерева в новый файл → fsync → rename → fsync каталога; файл без этого не уменьшается (D-018; docs/research/02, §2.4 п. 6). |
| **Усиление записи** (write amplification) | Отношение байт, записанных на диск, к байтам пользовательских данных; у COW B+tree высокое на одиночных коммитах, group commit его снижает (docs/research/02, §2.3). |
| **Эксклюзивная блокировка файла** | Файл БД открывает только один процесс (docs/research/02, §2.4 п. 7, DUR-9). |
| **B+tree** | Сбалансированное дерево поиска; данные в листьях, листья упорядочены — это даёт точный и префиксный поиск (docs/research/02, §2). |
| **COW** (copy-on-write) | Изменение через копию: страница не меняется на месте, вместо неё пишется новая (D-018, ADR 0003). |
| **CRC32C** | Контрольная сумма (полином Castagnoli) на каждой странице и мета-странице; реализуется самостоятельно и проверяется по тест-векторам (D-018, D-021). Обнаруживает ошибки, но не защищает от злонамеренной подделки (docs/research/02, §3.6). |
| **fail-stop** | При ошибке write/fsync движок перестаёт принимать записи, не подтверждает транзакцию и не повторяет fsync; восстановление — только с диска после перезапуска (D-019; fsyncgate, docs/research/02, §3.4). |
| **fsync каталога** | fsync файлового дескриптора каталога после create/rename/unlink, чтобы запись каталога попала на диск (D-019; docs/research/02, §3.1). |
| **fsyncgate** | Обнаруженная в 2018 году проблема: после ошибки `fsync()` повтор может вернуть успех, хотя данные потеряны (docs/research/02, §3.4). |
| **MVCC** | Многоверсионность: читатели работают на снимках и не блокируют писателя (D-018). |
| **txid** | Монотонный номер зафиксированной транзакции; хранится в мета-странице (D-018). |

## Эксплуатация и надёжность

| Термин | Определение |
|---|---|
| **Бэкап из снимка** | Онлайн-бэкап, согласованный на txid начала за счёт MVCC-снимка (D-025, ADR 0013). |
| **Детерминированная симуляция** (DST) | Прогон реального кода поверх симулированного диска (`SimDisk`) с ГПСЧ от seed и внедрением сбоев; любой сбой воспроизводится по seed (D-026; docs/research/02, §4). |
| **Перебор состояний после сбоя** (в стиле ALICE) | Построение всех допустимых состояний диска по трассе системных вызовов и проверка инвариантов после «перезапуска» (D-026; docs/research/02, §3.6, §4). |
| **Backpressure** | Отказ принимать новую работу при переполнении ограниченной очереди; клиент получает 503 или 429 (D-032, ADR 0017). |
| **LazyFS** | ФС в пользовательском пространстве, которая отбрасывает несброшенные данные и эмулирует потерю питания (D-026; docs/research/02, §4). |
| **RPO / RTO** | Допустимая потеря данных (сколько подтверждённого можно потерять) и допустимое время восстановления (docs/research/03, §7.4, CUJ-7). |
| **Tier 1 / tier 2** | Уровень поддержки платформы: tier 1 (Linux) — полные гарантии и crash-тесты в CI; tier 2 (Windows, macOS) — поддержка с задокументированными оговорками (D-023, ADR 0014). |

## Процесс и метрики

| Термин | Определение |
|---|---|
| **Гейт** | Финальная проверка цикла EGM; в проекте его закрывает оркестратор как прокси заказчика, а не человек (D-008). |
| **ADR** (Architecture Decision Record) | Запись одного архитектурного решения с контекстом, вариантами и последствиями; в BUDB — формат MADR 4.0 со статусами Nygard, неизменяема, замещается новой (D-005; docs/research/01, §A3). |
| **Capability** | Связная область поведения системы, у которой есть своя спецификация OpenSpec (`specs/<capability>/spec.md`); список из 15 — D-029. |
| **CUJ** (Critical User Journey) | «A sequence of tasks that is a core part of a given user's experience»: персона → цель → задачи с измеримым критерием успеха (docs/research/01, §A1). В BUDB — CUJ-01…CUJ-10 (D-028, `docs/cuj.md`). |
| **Elephant** | Сессия оркестратора с полным контекстом: хранит знания, принимает решения, ведёт журнал решений (D-001; Rensin, docs/research/01, §A2). |
| **Error budget** | Допустимая доля плохих событий за окно: 100 % − цель SLO (docs/research/03, §7.1). |
| **Fact Grounding** | Привязка каждого нетривиального утверждения к проверяемому источнику; непроверенное помечается (docs/research/01, §A5). |
| **Goldfish** | Свежая сессия агента без памяти: получает только узкую задачу и нужные файлы; так проверяется самодостаточность документа (D-001, D-006; docs/research/01, §A2). |
| **LLM-expert review** | Ревью агентами-экспертами (не автором) по заранее составленной рубрике (docs/research/01, §A4). |
| **NFR-SCRATCH** | Правило «с нуля»: весь код постоянного хранения пишется в проекте, зависимости — только из allowlist, проверка cargo-deny (D-021, ADR 0006). |
| **OpenSpec** | Инструмент спецификаций: `proposal.md`, дельты `specs/**/spec.md`, `design.md`, `tasks.md`; закреплённая версия 1.15.0 (D-003; docs/research/01, часть B). |
| **SLI** (Service Level Indicator) | Измеряемый показатель качества сервиса, обычно доля хороших событий среди допустимых (docs/research/03, §7.1). |
| **SLO** (Service Level Objective) | Целевое значение SLI за окно, например «p99 поиска ≤ 100 мс» (docs/research/03, §7.1; числа BUDB — D-024, `docs/cuj.md`). |
